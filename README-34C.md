# V0.34C — Multi-Tile Settlement V1 + Spatial Index V1

**기준선:** `V0.34B-HF1` · **날짜:** 2026-10-09  
**상태:** 최초 구현 및 통제 회귀검증 완료 / 실제 50~100년 신규 세계·고인구 성능 비교 필요

## 개발 목표와 변경 범위

- `World.v34b.settlements[]`의 기존 독립 Settlement 엔티티를 유지하면서 `schemaVersion:2`를 도입한다.
- ACTIVE Settlement의 `tileIds`가 최대 5개까지 들어갈 수 있다. 개별 `Tile.ownerId`는 국가 영유권, `Tile.settlementId`는 정착지 소속을 표시한다.
- 국가·타일·Person의 물리적 상태는 유지한다. **식량과 생산, 건물, 주거, 시장 Gold, 장비를 다른 타일에 복제하거나 통합하지 않는다.**
- 정착지 경계를 실제로 병합·분할한다. 단순 표시용 그룹이 아니다. 정착지 ID는 병합과 영토 변경 후에도 명시적인 이력 규칙을 따른다.
- 분기별 공간 평가, O(1) 타일→정착지 참조, 하루 동안 재사용하는 집계 캐시, 계측치를 통해 후속 성능 향상 기반을 마련한다. **이번 구현만으로 SIM ms/day 10~20% 향상은 검증되지 않았다.**

## 접근시간 규칙

기존 운송 시스템의 `TERRAIN[].tradeCost`를 1일 환산 공간 비용으로 사용한다. **이는 물리적 경과일 자체를 시뮬레이션하는 신규 시스템이 아니다.** 수송 거리와 방향별 진입비용의 근사값이다.

- 동일 국가가 소유한 육상 타일끼리 **4방향 인접**해야 한다. 다른 국가/중립 영토를 우회로로 쓰지 않는다.
- 비용은 진입 타일의 `tradeCost`이고, 해당 국가에 `ROADS` 기술이 있으며 타일에 컨디션 25 이상인 실물 도로가 있으면 `×0.62`를 적용한다.
- **병합:** 병합 후보 전체의 연결 안에서 기존 두 중심지 중 하나를 선정하고, 모든 구성 타일에 대해 `중심 → 타일` 및 `타일 → 중심`의 최단 비용이 각각 `≤1.00`이어야 한다. 양쪽 후보 중 적어도 하나에 거주 인구 또는 경제 시설이 있어야 한다.
- **최대 크기:** 5타일. 기존 수도 중심지와 오래된 Settlement를 ID 보존 우선순위에 반영한다.
- **지속 조건:** 분기별 평가에서 병합 요건이 처음 성립한 뒤 90일 이상 지속돼야 실제 병합한다.
- **분할:** 이미 병합된 Settlement의 중심지 왕복 도달비가 `>1.15`인 상태가 180일 지속되면 독립 정착지로 분리한다. 영유권이 변경돼 국가가 달라지거나 물리적 연결이 끊어진 경우에는 지연 없이 분할한다.
- **일시 점령:** `v33OccupierId` 변경은 소유권 변경이 아니므로 정착지 소속도 그대로이다.

상기 수치는 C1 개발 기준이다. 교통 기술 발전에 따라 거대 도시의 반경이 확장되는 기능은 후속 버전 검토 대상이다.

## ID·생애주기

- 새 정착지는 `st-0000001` 스타일의 고유 ID를 발급하고 `nextSettlementSeq`가 증가한다.
- 병합 시 하나의 ACTIVE Settlement ID를 보존하고 다른 기록은 `MERGED`, `mergedIntoId`, `mergedCalendarDay` 상태로 보존한다. 병합된 ID는 재사용하지 않는다.
- 일반 비중심 타일을 영구 양도하면 양도 타일에 별도 Settlement ID를 발급한다. 기존 나머지 Settlement ID는 유지한다.
- 중심 타일이 영구 양도되면 원래 ID는 중심 타일을 따라가고, 다른 국가에 남은 타일은 신규 ID를 발급한다.
- 영유권이 완전히 사라지면 `ABANDONED` 기록을 남긴다. 도로 상태 악화 분할이나 영토 재획득은 기존 양도 ID를 되살리지 않는다.
- 타일의 영유권 변경 감지 로직은 34B에 있던 1:1 전용 분기 대신 **34C Multi-Tile 분할/연결 확인 경로로 위임**한다.

## 성능 구조

1. **이벤트 경로:** 타일 `ownerId`의 실제 변화가 일어날 때만 해당 Settlement 기록을 즉시 변경한다. 매일 세계 모든 Settlement를 재생성하지 않는다.
2. **분기별 검토:** 90일 간격으로 물리적으로 경계를 공유하는 후보만 검사한다. `review` 횟수·병합·분할 횟수·실측 검토시간을 집계한다.
3. **공간 캐시:** `VSim.V034C.aggregate(world, settlementId)`가 동일 날짜의 Settlement 주민·시설·재고 요약을 재사용한다. 주민은 가능하면 기존 V26의 epoch 무효화 주민 인덱스를 이용한다.
4. **기존 캐시 존중:** V26 주민 인덱스, V27/29/32 물류·노동 캐시를 중복 구현하지 않는다. Person 행동·경제 계산식과 기존 시뮬레이션 루프는 그대로 유지된다.
5. **계측:** `settlementReviews34C`, `settlementReviewMs34C`, `settlementCacheBuilds34C`, `settlementCacheHits34C`, `activeSettlements34C`, `multiTileSettlements34C`, `settlementMerges34C`, `settlementSplits34C`, `settlementErrors34C`를 Snapshot CSV에 추가한다.

이러한 구조는 후속 최적화를 위한 인덱스를 추가한 것이다. **기존 고비용 Person/경제 알고리즘 전체를 정착지 수준으로 묶는 작업은 수행하지 않았다.** 정확한 10~20% 속도 향상 여부는 1,000~2,000명 규모의 동일 조건 벤치마크가 필요하다.

## 게임 관찰 UI

- 지도 상단 **`정착지 경계: 끔/켬`** 버튼을 누르면 동일 국가 안의 다른 Settlement 경계를 밝은 선으로 표시한다.
- 각 중심지에 작은 중심 표시가 생긴다. 기존 국가 간 경계·군사 레이어는 유지한다.
- 타일 상세에는 실제 Settlement ID, 중심 타일, 포함된 타일 번호/수, 정착지 총인구 및 시설 수, 중심지 왕복 환산시간을 표시한다.
- 기존 국가 상세 화면에서 사용하는 역사적 “정착지” 표현 및 타일별 경제 통계는 **34D 전까지 물리적 Tile 관측치**로 남는다. `V0.34C`의 실제 Settlement 수와 동일하다고 해석하면 안 된다.

## API 및 저장

- `VSim.V034C.ensure(world)` — 34B 등록 구조를 단일 또는 다중 타일 schema v2로 준비
- `VSim.V034C.inspect(world)` — 정착지 이중 할당·고아 연결·소속 국가·4방향 연결·ID 이력을 검사
- `VSim.V034C.byTile(world, tileId)` — 실제 Tile의 정착지 조회
- `VSim.V034C.aggregate(world, settlementId)` — 읽기 전용 공간 캐시
- `VSim.V034C.review(world)` — 강제 분기 병합/분할 평가(테스트 전용)
- `World.v34c` — 분기 평가 시점, 병합/분할 관찰 시점, 카운터 저장

34B-HF1 세이브를 참고용으로 읽을 수 있으나 구버전 호환성은 정식 종료 조건이 아니다. 새 게임에서 34C로 저장한 파일을 34C로 복원하는 안정성이 더 중요하다.

## 로컬 대용량 검증

`save-validator.html`이 34B 스키마 v1과 34C 스키마 v2를 구분한다. 34C일 경우 ACTIVE/MERGED/ABANDONED·타일 유일 소속·동일 국가·중심지 멤버십·4방향 연결성·최대 5타일 규칙을 검사한다. **저장 데이터만으로 과거 각 분기별 접근비용을 재연하거나, 실제 경제를 재실행하지는 않는다.** 파일 업로드 없이 로컬에서 감사 보고서만 내보낸다.
