# Village Observer V0.34H4C — Storage Overflow Redistribution & National Border V2

## 배포 기준

- 기준: `V0.34H4B`, 현재 릴리스: `V0.34H4C`.
- **이번 버전은 시뮬레이션 규칙 변경을 포함함**: 기존 초과 석재를 삭제하지 않고, 신규 *일반* 석재 입고를 전체 Settlement 저장 용량으로 제한하며, 초과분을 실제 국가 내부 경로로 운송한다.
- 국가간 국경의 검은색과 H4B 굵기(기본 1.61px)를 유지한 채, 국가-중립 육지/국가-수역의 접경도 검은 외곽선으로 표시한다. 중립지-물, 물-물 사이에 새 검은선을 만들지 않는다. `선택 강조` 모드 불변.
- 세계 탭 국가 비교의 H4B 색상 막대는 수정하지 않는다.

## 물리 석재 비축·이동

1. `NS.Village.prototype.depositAt`에서 석재 `stone`의 일반 입고량을 현재 **Settlement 공동 재고/공동 저장 상한**에 맞춰 제한한다. 같은 Settlement의 다른 타일에 빈 공간이 있어도 공동 상한 초과 입고는 허용하지 않는다. 식량·목재·철 계열의 입고 정책은 변경하지 않는다.
2. 영토 포기·재개척·창고 축소로 이미 존재하는 물리 석재 초과분은 삭제·신규 생성하지 않는다. 건설 자원 반환과 실패한 자원 이전의 **이미 소유한 물자 복원**은 신규 비축과 분리한다.
3. 매 3 *calendar day*에 국별 초과 Settlement를 검색한다. 같은 국가의 별개 Settlement 중 여유 저장 공간이 있고, 점령·차단되지 않은 실제 경로와 `internalLogisticsCapacity(...,'stone',false)`의 양의 운송 능력이 있는 목적지로 물리 재고를 이전한다. 같은 Settlement 내부에서는 새 배송을 만들지 않는다. 한 국가는 한 주기 최대 3개 석재 배송으로 제한한다.
4. 목적지 탐색은 지리적으로 가까운 후보 12개부터 시작하고, 접근 가능한 목적지가 없으면 두 번째 12개까지 확장한다. 이는 전국 경로 탐색으로 인한 반복 비용을 제한하는 정책이다. 후보 범위 내에 정상 경로가 없으면 재고를 유지하고 다음에 재시도한다.
5. 출발지 출고 → 도착지 입고 → 합계 보존식을 확인하며, 도착지 입고가 거절되거나 보존식이 어긋나면 출발·도착의 **실물 타일 재고를 복구**하고 진단 카운터를 증가시킨다.
6. 긴급 식량 배송을 우선한다. 식량 G2A가 같은 날 동일 출발·도착 타일쌍으로 운송한 양은 석재 운송 용량에서 차감한다. 전체 물류망의 포괄적인 글로벌 예산 모델은 이번 버전에서 도입하지 않는다.

## 관측

- Devlog `worldSummary.v034h4c`에 물리 운송 횟수·수량, 신규 비축 거부, 보존식 오류·반환 실패, 차단 사유 및 **남은 석재 초과량** 집계.
- 실행 중 한 번의 실제 배송은 `STORAGE_OVERFLOW_TRANSFER34H4C` 이벤트로 기록한다.
- 기존 H4A 경량 진단 JSON과 H4 감사는 유지. 세계 → 고급 도구 → 기존 상세 진단에서 **H4C · 초과 석재 운송 진단 JSON** 버튼으로 물류 집계와 기존 물리 재고 분석을 함께 받을 수 있다.
- H4A 이전에 발생한 90년의 벨른 5개 초과 정착지(총 약 926.73)는 별도의 실제 Save JSON 없이 현재 코드에 주입해 재주행한 것이 아니다. 과거 원인의 전수 확정이나 장기 분산 완료를 주장하지 않는다.

## 배포·검증

- 프로젝트 루트: `npm run build`, `npm test`.
- 오프라인: `index-standalone.html` 또는 `dist/standalone/index.html`.
- GitHub Pages: **루트 `index.html`과 `dist/hosted/assets/`를 함께** 반영 후 Commit → Push.
- 169개 레거시 보호 원본 블록 SHA 유지. 변경한 자산은 신규 `src/bootstrap/v034h4c.js`, `tools/h4c-transform.mjs` 및 반송 스코프/물류 관측 API 두 개에 한정. 원본 protected JS 파일은 수정하지 않는다.
- 기술 43개, CSV V2 1,683열 유지. AI·전쟁·주민 신진대사·기술·Gold 산식은 직접 조정하지 않지만, 석재 비축/물류의 실제 결과가 이후 건설 의사결정에 영향을 줄 수 있으므로 H4B와 전체 장기 시뮬레이션 상태가 일치할 것으로 기대하면 안 된다.

## 알려진 한계

- 사용자 실제 90년 Save JSON을 불러 실제 926.73 초과량이 얼마의 기간 안에 해소되는지 시험하지 못했다. **목적지 저장 여유나 경로가 없으면 합법적으로 초과 상태가 유지된다.**
- 신규 배송은 현재 경로량 상한과 3일 맥동을 사용하지만, F0 전체 150년 ×10 SIM/BATCH 목표 성능은 검증되지 않았다.
- 원자적 롤백은 H4C 전용 배송에 구현했고, 주요 기존 거래의 일반 석재 반송 루틴은 H4C 반환 스코프로 보호한다. 드물고 오래된 레거시 경로 전체의 추가 반송 검증은 확장 검사 대상으로 남는다.
