# V0.34G1 — 타일·정착지 용어 정비 / 식량 물류 감사 V1

**개발일: 2026-10-16 · 기준선: V0.34F3 (CLOSED)**

## 핵심 요약

- 공식 한국어: `Tile = 타일`(지도 격자, 건물 입지, 점령, 물리적 경로), `Settlement = 정착지`(하나 이상의 타일을 포함하는 공동 주거·식량·노동·경제권), `Nation = 국가`, `Person = 주민`. `마을/도시`는 정착지의 발전 상태를 나타낸다.
- 국가 화면 상단에 **정착지 수와 영토 타일 수를 함께 표시**한다. 소속 타일 정보창에 물리 타일 ID/소속 정착지 ID와 소속 타일 수를 표시한다. 과거 정착지별 장기통계였던 선택 범위는 실제 데이터 단위에 맞춰 **'타일 (기존 장기 통계)'**라고 명시한다. 과거 생성된 역사 기록·레거시 텍스트 전체를 일괄 변경하지는 않는다.
- 기존 V0.32E2 긴급 식량 물류가 타일별 인구로 식량 비축일을 나누고 D3 공동 재고를 중복 공급원으로 검토하는 점을 **관측만 한다**. 다음 단계 G2에서 정착지 전체 인구/공동 재고에 따라 식량 수요를 정착지당 한 번 판단하고, 타일 단위 최적 물류 경로로 실제 배송한다.
- D3 공동 재고, F0~F3 배급·신진대사, AI 의사결정, 노동, RNG, 운송량, Gold 회계, 전쟁 규칙은 G1에서 변경하지 않았다.

## 물류 감사의 실제 작동 범위

`src/legacy/069.js`를 *원본 수정 없이* `tools/g1-transform.mjs`에서 빌드 시 관측 호출만 덧붙인다. V0.32E2 기존 6달력일 식량 인덱스 작성 시점에만 `observeFoodIndex`를 호출하며, 실제 운송 가능성 검사(캐시 미스)의 `observePair`, 실제 `NATIONAL_FOOD_RELAY32D5` 배송의 `observeShipment`를 별도 계측한다.

`V034G1.group()`은 기존 인덱스의 개인별/타일별 `pop`, `stock`, `severe`, `critical`, `days`를 **정착지 ID로 합산**한다. 비교 지표는 구형 E2 판단식(`stock/(population*0.36)` 비축일)을 사용하여 단위별 차이만 분리한다. 이것은 **F0의 실제 3일 배급 수요식이 아니다.**

| 감사 항목 | 해석 |
| --- | --- |
| `hiddenShortageTiles` | 타일별로는 긴급 대상이 없지만 정착지 전체로는 긴급한 경우의 소속 타일 수 |
| `falseDonorTiles` | 타일별로 공급 가능해 보이지만 정착지 전체로는 공급 자격이 없는 경우의 타일 수 |
| `duplicateDonorCandidates` | 같은 정착지가 중복 공급원으로 평가될 수 있는 타일 수(첫 번째 제외) |
| `duplicateUrgentReceivers` | 정착지 하나에서 중복 긴급 수요로 표시된 추가 타일 수 |
| `sameSettlementFallbackPairs` | D3 내부 물류용량이 0인데 구형 E2 대체 용량으로 동일 정착지 쌍이 살아난 경우 |
| `sameSettlementShipments` | E2 긴급 물류에서 동일 정착지로 실제 이동 처리된 횟수 |
| `legacyManhattan`, `bestManhattan` | 실제 배송된 타일 쌍과 구성 타일 쌍의 맨해튼 거리 비교. 도로/지형을 포함하는 **실제 물류비 절감량이 아님** |

**범위 한계:** G1 감사 지표는 *E2 국가 내 긴급 식량 물류 경로에 한정*한다. 다른 구형 V27/V28, 정기 상거래, 외교 교역, 점령 군사 보급 전체를 계측했다고 주장하지 않는다. 동적 감사를 저장하지 않고 World별 메모리에 제한적(최대 1,200행)으로 보관하여 세이브 복귀 시 감사 누적 횟수가 초기화된다. 기존 세계 상태와 보존식에는 영향이 없다. `pairSamples`는 E2 캐시 미스 시 계산된 쌍만 포함한다.

## 실행·데이터 수집

1. `dist/standalone/index.html` 또는 루트 `index-standalone.html`을 브라우저에서 연다. GitHub Pages에서는 루트 `index.html`을 이용한다.
2. 진행된 F3 세이브를 불러오거나 새로운 게임을 실행한다. **여러 타일을 가진 정착지**가 충분히 생길 때까지 주행한다.
3. 개발 로그/데이터 내보내기 구역의 **`G1 물류 감사 CSV`** 버튼을 클릭한다. 이 CSV는 기존 Snapshot 1,683열에 추가한 것이 아니라 **별도 30열 CSV**이다.
4. Devlog JSON의 `worldSummary.v034g1`에 집계 카운터도 기록된다. 분석 시 Devlog JSON, 전체 Snapshot CSV, G1 물류 감사 CSV를 함께 전달한다.
5. CSV에 헤더만 있고 데이터가 없다면 아직 다중 타일 정착지에 관련된 불일치/배송 관측이 없다는 뜻일 수 있다. 자연주행에서도 반드시 버그가 발생한다고 단정하지 않는다.
