# V0.34D3B3 — Performance Regression Audit & Optimization V1

**날짜:** 2026-10-12 · **기준 버전:** V0.34D3B2 · **범위:** 성능 개선 및 검증/관측만. 주요 경제·AI·전쟁 밸런스 불변.

## 1. 목적과 근거

과거 V0.34C1/D0/D1 PC 주행 대비 D3B2 후기 SIM 처리시간 증가가 관측되었습니다. 서로 다른 시드·인구·영토·기기·배속에서 기록되어 있으므로 원인과 회귀율은 미확정입니다. B3은 일상적인 D3 식량/자원 연산에서 검증 가능한 중복 작업을 줄이는 1차 최적화입니다.

## 2. 변경 내용

- `src/bootstrap/v034d3.js`: 같은 Settlement의 구성 타일 목록을 각 재고 조회에서 재생성하지 않습니다. 실제 타일의 `ownerId`, `settlementId`, `v33OccupierId`가 변경되면 기존 타일 속성의 의미를 유지하는 접근자에 의해 캐시가 무효화됩니다. 그룹 레코드의 `tileIds` 배열이 병합·분할로 교체되거나 그룹 크기가 달라져도 새로 계산합니다. 물리 자원량, 건물 조건, 주민 위치는 캐시하지 않습니다.
- 동일한 `settlementReserveDays()`의 인구 분모는 기존 V26의 살아 있는 주민 `byHome` 인덱스를 이용해 Settlement 구성 타일의 주민만 순회합니다. 이 인덱스는 주민의 생사·거주지·명부 변화 시 무효화됩니다. 나이값은 실제 Person 객체에서 매번 읽습니다.
- `src/bootstrap/v034d3a.js`: Food Flow 수확 지표 7개 및 입고 지표를 한 번의 30일 행 조회로 일괄 기록하고, 정착지 타일 목록 비교에서 문자열 `join()`의 반복 생성을 제거합니다. 모든 지표 값·계산식·CSV 구조는 동일합니다.
- `src/bootstrap/v034d3b3.js`: 최종 UI 버전, 패치노트, 최신 저장키, CSV·Devlog 파일 이름을 갱신합니다. B2 저장 이식과 저장 왕복을 지원합니다. 선택형 시간 샘플러는 기본 OFF입니다.
- `save-validator.html`: B3 저장에 13타일 및 중심 Manhattan 반경 2 조건을 적용합니다.

## 3. 측정

두 버전 실제 Standalone 빌드를 동일 Node V8 컨텍스트·동일 시드·13타일 도로 Settlement·주민 256명 조건에서 로딩한 뒤, 공동 재고와 식량 비축일 조회 묶음을 각 20,000회 수행했습니다. 6번씩 교차 측정한 중앙값: **B2 1,977.63ms / B3 542.33ms (3.65배)**. 이 수치는 특정 읽기 연산의 인공 벤치마크입니다. 월드 전체 SIM/일·Wall/일의 개선율로 환산할 수 없으며, 사용자의 PC 66년 저장파일을 직접 재생한 것이 아닙니다. 같은 초기 랜덤 시드에서 18일을 실제 진행한 비교의 3개 체크포인트에서는 국가·자원 요약 및 RNG 호출 수가 같았습니다.

## 5. 미완료 과제

- 실제 동일 PC·동일 초기 저장상태·동일 배속에서 B2/B3 50~75년 장기 A/B 테스트.
- 하루 SIM/Wall 세부 프로파일링에서 나머지 주요 병목(물류 경로, 분기별 국가 전략, UI 렌더 등) 분리.
- B2 장기 주행에서 남은 Food Flow 잔차 53개 구간 및 D3C 식량 운송 정책 개선은 이번 패치 범위 밖입니다.
