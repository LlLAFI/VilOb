# Village Observer V0.34D3B1 — Road-Connected Settlement Radius 2

기준선: **V0.34D3B** · 2026-10-12 · 정착지 공간 통합 및 개척 연속성 패치.

## 목적과 실제 동작

V0.34C 공간 통합 엔진의 **도로가 연결된 이상적인 평야·초지** 정착지 범위를 기존 중심 1타일+인접 4타일에서 한 겹 더 확장했습니다. 4방향 인접(맨해튼 거리) 기준 **중심 1 + 거리 1의 4 + 거리 2의 8 = 최대 13타일**입니다. 대각선 5×5 정사각형/25타일이 아닙니다.

| 정책 | D3B | D3B1 |
|---|---:|---:|
| 병합 허용 접근비 (`JOIN`) | 1.00 | **1.24** |
| 분할 완충 접근비 (`SPLIT`) | 1.15 | **1.40** |
| 최대 구성 타일 (`MAX_TILES`) | 5 | **13** |
| 중심으로부터 최대 맨해튼 거리 | 접근비/타일상한 간접 제약 | **2** (명시적) |
| 병합 대기 / 분할 대기 | 90일 / 180일 | **유지** |
| 도로 이동비 계수 | 0.62 | **유지** |

정상 도로 2칸의 접근비는 `0.62 + 0.62 = 1.24`입니다. 접근비는 **왕복 모두** 만족해야 하며, `ROADS` 기술과 해당 타일 도로 상태 **25 이상**이 실제 효과 조건입니다. 지형에 따라 통합 가능한 도달 범위는 더 작을 수 있습니다. 중심에서 3칸 떨어진 타일은 도로가 충분히 빨라도 통합하지 않습니다.

- 같은 국가가 소유한 서로 붙어 있는 실제 타일만 병합합니다. 중심지는 기존 Settlement의 실제 `coreTileId`이며, 가상의 공간 중심을 별도로 생성하지 않습니다.
- 병합할 그룹 안에 기존 개발된 타일이 있어야 합니다. 모든 타일이 도로만 있는 경우 처음부터 큰 Settlement로 자동 병합하지 않던 기존 안전 조건을 유지합니다.
- 통합 중에도 원래 Person의 거주/근무 타일, 건물, 물리 재고, Gold, 군사 배치, 국가 소유권이 유지됩니다. 공동 Settlement 경제·주거 정책만 확대된 실제 구성에 맞춰 적용됩니다.
- 거리가 멀어지거나 도로가 훼손되어 분할 완충 접근비(1.40)를 충족하지 못하면 **180일의 유예 이후** 분리됩니다. 임시 교통 차단으로 즉시 모든 Settlement가 갈라지지 않습니다.

## 확장 후보 선택의 소규모 수정

V20/V21/V24 일반 개척에서 **실제 개척 예정지가 기존 Settlement로 통합될 여지**가 있으면 후보 점수에 최대 **+14점**을 부여합니다. 단, 신규 타일은 보통 아직 도로를 지을 수 없으므로, 기존 도로망과 `ROADS` 기술을 갖추고 새 타일에 **나중에 정상 도로를 설치한다는 조건**으로 접근비를 사전 추정합니다.

- 도로는 **자동으로 생성되지 않습니다.** 도로를 실제로 건설하여 연결 조건을 충족한 뒤, 기존 90일 병합 조건을 통과해야 통합됩니다.
- 후보 보너스는 통합 가능한 실제 정착지의 규모가 **13타일 미만**, 예상 신규 타일이 기존 중심에서 거리 2 이내, 기존 길 및 예상 연결 구간의 양방향 접근비가 **1.24 이하**일 때만 적용됩니다.
- 저렴한 후보를 우선 선택하는 기존 Gold 견적, 개척민·식량·자재 제약과 기본 AIProfile 성향은 유지합니다. 높은 자원 가치/전략적 가치가 있는 다른 후보는 여전히 선택될 수 있습니다. 즉, **강제 우선이 아니라 제한적인 가산점**입니다.
- 해당 후보 판단은 평시 개척 후보 평가에만 연결되고 Recovery Escape의 별도 후보 점수는 변경하지 않습니다.

## 구현 및 호환성

- `src/legacy/`의 보호된 **165개 JS + 4개 CSS** 원본은 바꾸지 않습니다. 빌드 변환기의 `tools/d2-transform.mjs`에 C 엔진의 상수와 반경·검사 게이트에 대해 **고유성 검증된 앵커**를 추가했습니다.
- 새 `src/bootstrap/v034d3b1.js`는 신규 후보 선택 편향, 버전·저장/내보내기, 패치노트, Devlog 정책을 담당합니다.
- 새 저장 버전·키: `V0.34D3B1`, `village-observer-v034d3b1`. 기존 **D3B JSON / 브라우저 저장**을 D3B1로 이식하며, D3A2 호환 경로도 보존합니다. 이전 저장의 물리적인 재고·인구·건물은 이식 과정에서 변경되지 않습니다. 통합은 정상 분기 검토/도로 조건 충족 이후에 일어납니다.
- `save-validator.html`: **D3B1의 schema v2 최대 13타일 + 중심 반경 2칸** 검사. 이전 D3B 및 과거 버전은 기존 5타일 제약을 유지합니다.
- CSV: Snapshot V2 **1,683열**, Food Flow **48열**, Economy **24열** 유지. 원본 169블록 SHA-256 유지.
- 배포: standalone `dist/standalone/index.html` 또는 `index-standalone.html`; GitHub Pages는 `dist/hosted/index.html` + `dist/hosted/assets/` 전체 게시.

## 이 버전에서 변경하지 않은 사항

목재·식량·석재 생산 계수, D3B 초반 밸런스, 개척 비용, AI 개척 간격, 생존모드/Recovery, 교역·도로·군사 이동비, 공동 물리 재고·노동량, 전투 및 재정 보존식은 그대로입니다.

**열려 있는 별도 문제:** 사용자의 D3B 59년 자연주행에서 발견된 **V24 지역 개척 착공 식량 10/13의 Food Flow 계측 누락**, 과도한 정착지 분산 및 라엔의 평시 인구 붕괴는 **본 패치에서 해결했다고 주장하지 않습니다**. 정착지 반경 확장이 도움을 줄 가능성은 있지만, 원인 분리 검증이 필요한 후속 작업입니다.
