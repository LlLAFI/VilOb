# Village Observer V0.34H4B — Boundary Refinement & Storage Investigation

## 기준 및 변경 범위

- 기준 버전: `V0.34H4A`; 새 버전: `V0.34H4B`.
- 지도 「정착지 경계: 전체」의 두 겹 외곽선 **각각 70%**: 내부 색상선 `max(1.6, cell×0.075)×0.7`, 외곽 윤곽선 `(원래 내부 폭+2.1)×0.7`. 선택 강조는 그대로.
- H4A의 **서로 다른 국가 간 마지막 검은 경계** 역시 `max(2.3, cell×0.115)×0.7`. 최종 렌더 순서 및 검은색 유지.
- 세계 탭 국가 비교의 국가 이름 왼쪽에 통계 탭과 같은 `.h4a-nation-bar`(4×16px)를 렌더. 색상은 `NS.NATION_COLORS[v.id]`, 커스텀 국가색 적용 후 지도와 일치. 정렬, 멸망국 표시와 원래 국가 이름 버튼의 이동 기능을 유지.

## 석재 초과 조사 결과 및 처리 정책

90년 H4A 경량 진단 JSON에서 벨른 정착지 5곳의 현재 저장 초과량 합계는 **926.73**. 모두 `UNEXPLAINED_OVERFLOW`이며 현재 건물 상태가 100이고, 타일 #136, #117, #116, #99, #100~102가 포기·연결 해제·재개척 경로에 포함됐다.

**재현된 실제 코드 경로:** 구형 `src/legacy/008.js`의 `Village.pruneDisconnectedTerritory`는 연결이 끊긴 타일의 `ownerId=null`, `buildings=[]`로 만들지만 `t.stocks`는 변경하지 않는다. 격리된 1개 타일에 석재 341.51을 담고 연결 해제를 실행하면 석재가 그대로 남는다. 이를 전초기지로 다시 소유한 제어 시나리오에서 새 물리 저장 용량은 65이므로 276.51 초과가 가능하다. **이 시나리오는 원인 가능성을 입증한 것이며, 실제 다섯 타일의 최초 석재 유입 시각·원인을 모두 증명한 것은 아니다.**

- 보존된 기존 재고 자체를 신규 자원 생성 버그로 취급하지 않는다.
- 기존 초과분은 삭제/자동 이전하지 않는다. 저장 용량을 임의로 증설하지 않는다.
- 신규 입고의 저장 상한 위반 여부는 그 경로의 시작 세이브/직전 계측 없이 결론 내리지 않는다.
- H4A의 경량 JSON·첫 관측/30일 주기/토폴로지 변동 관측은 그대로 유지. 이번에는 추가 저장 물류 규칙 변경 없이 재현 테스트를 추가했다.

## 배포 및 호환성

- **Stand-alone:** `index-standalone.html` 또는 `dist/standalone/index.html`.
- **GitHub Pages:** 저장소 루트 `index.html`과 `dist/hosted/assets/`를 함께 게시할 것. GitHub Desktop에서 프로젝트 전체 변경 사항을 Commit/Push.
- `npm run build` 후 `npm test`. 확장 동일성 검사 `H4B_DAYS=30 node tests/test-h4b-parity.cjs`.
- 지원되는 H4B/H4A/H4/H3/H2A/H2/H1/H0/G5 저장 포맷을 불러오며, H4B 전용 로컬 저장 키를 사용. 이전 H4A 로컬 키 fallback 유지.
- 169개 레거시 보호 블록과 CSV V2 1,683열, 43개 기술은 그대로 유지. AI/Person/전쟁/식량/자원·Gold 회계/RNG/시뮬레이션 동작 순서에 변경 없음.

## 알려진 제약

사용자 90년 전체 Save JSON이 없어 그 세이브 자체의 로드/이어달리기와 원래 다섯 타일의 역사적 초과 인과관계는 직접 검증하지 않았다. 또한 전체 150년 장기 성능, 90일 확장 parity, 오래 걸리는 모든 과거 버전 확장 테스트는 수행하지 않았다. 새 UI와 계산의 결과 동등성은 PC/모바일 UI 및 H4A↔H4B 30일 비교로 확인했다.
