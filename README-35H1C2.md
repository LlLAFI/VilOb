# V0.35H1C2 — Simulation State & Observation Separation V1

This release introduces four non-interchangeable domain terms:

| Korean | Runtime / design concept | Lifecycle |
| --- | --- | --- |
| 시뮬레이션 상태 | `SimulationState` | Game-authoritative: always preserved for valid future behavior |
| 게임 사건 | `DomainEvents` | Game-side effects must execute whether or not a log is retained |
| 관측 텔레메트리 | `Observer` / legacy `Telemetry` | History and analysis; not generally safe to disable yet |
| 개발 진단 | `Diagnostics` | Opt-in profiling and troubleshooting; not game-authoritative |

## Concrete implementation

1. The **last `AI_DECISION` per nation** is retained as `world.v35h1c2.aiLast[id]` (ordinal day plus the original payload object). `src/legacy/024.js` (AI feasibility/fallback) and `src/legacy/093.js` (decision annotation) now resolve the latest decision through `NS.V035H1C2.SimulationState.lastDecision` when available. Unlike the former reverse search through `telemetry.entries`, the same-day decision survives log removal from the runtime array. The authoritative payload shares its live reference with the original logged event so legacy fallback annotations continue to mutate the **same** Devlog payload. The field is written during `World.serialize()` and rehydrated through `World.from()`; an older H1C1 save without it uses a one-time legacy log lookup when necessary. The existing checkpoint data format label remains `V0.35H1B1A`.
2. In the protected `src/legacy/126.js` call site, `WAR_DECLARED33 → repairWarTargets` is routed through `NS.V035H1C2.DomainEvents.legacyWarDeclared`, calling the **exact original** function at the **exact original** position in the legacy `Telemetry.record()` wrapper. This is an explicit domain-event seam, not a completely independent message bus. Other wartime hooks including `WAR_ENDED33`, occupation, and log-dedup remain unchanged and are registered as follow-up work.
3. Original telemetry `entries`, `snapshots`, `yearlySummaries`, D3A ledger, 1,683-column CSV, 43 technologies, all combat/Formation state, and debug diagnostic tools are unchanged. No producer is disabled and no history-retention rule is altered.
4. Static classification generated by `node tools/telemetry-inventory.mjs` inventories all **1,683 existing Snapshot CSV columns** by descriptive domain. Each is `REVIEW_REQUIRED`, `safeToDisable:false`: classifying an output column does **not** prove that its legacy producer is side-effect free. The evidence registry highlights specific historical dependencies (`legacy/019`, `024`, `093`, `110`, `114`, `125`, `126`, etc.).
5. The World / Advanced Tools H1C2 panel exports a lightweight **terminology, boundary, and counters** report to JSON. The UI does not expose an unsafe global telemetry switch.

## Deliberately not implemented

- Blanket `Telemetry.record()` or Snapshot OFF switches.
- Domain event bus replacement for all prior `record()` side effects.
- Migrating every `AI_DECISION` log enrichment and older event-dependent AI heuristic.
- Removing/shortening 30-day food ledgers or annual/snapshot histories.
- Default Core/Detail CSV separation and legacy field pruning.
- E4/F5A hotpath structural optimization: deferred until boundaries can be safely separated.

## Acceptance criteria

- H1C1 vs H1C2 120-day deterministic world, RNG, complete events, snapshots (excluding runtime timing), yearly summaries and D3A ledger equality.
- Same wartime `WAR_DECLARED33` record sequence and actual target invariant repair.
- Recorded AI decisions can be read from SimulationState even with the runtime entries array temporarily empty.
- `v35h1c2` state survives gzip/JSON checkpoint and old H1C1 checkpoint imports.
- Protected 169 baseline SHA blocks, tech 43, Snapshot CSV 1,683, 166 hosted JS requests.

## Future roadmap

H1C3 should migrate remaining **actual gameplay event side effects** out of observation chains, introduce safe, explicitly gated opt-in diagnostic suppression only after ON/OFF world parity, and then optimize the E4/F5A snapshot hotspot. The diagnostic taxonomy is not the same as a finished removal plan.
