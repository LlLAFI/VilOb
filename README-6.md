# Village Observer V0.28 — Patch 1

Village Observer는 실제 주민(Person)의 생활과 선택이 **Settlement → Nation → World** 변화로 이어지는 browser-based bottom-up 사회 시뮬레이션입니다.

V0.28의 본래 주제는 **후기 정착구조·도시화 V1**입니다. 이번 Patch 1은 V0.28 장기주행을 약 88년까지 관찰하면서 확인된 문제를 수정하는 유지보수 패치입니다.

저장 데이터의 버전은 계속 `0.28`, localStorage 키도 계속 `village-observer-v0-28`을 사용합니다. 즉 별도 세대의 세이브 형식으로 갈라지지 않습니다.

## Patch 1 핵심 변경

### 1. 건물 시대명과 주거 스케일 정리

건물 내부 ID는 그대로 유지합니다.

예:

- `house`
- `row_house`
- `collective_house`
- `trading_post`
- `market`

세이브·기존 로직은 이 ID를 그대로 사용하고, UI 표시명만 건물의 **건축 세대**를 드러내도록 정리했습니다.

중요한 원칙은 다음과 같습니다.

> `고대`라는 접두사는 국가의 현재 최고 기술시대를 뜻하지 않고, **그 건물 자체가 고대형 건축 세대라는 뜻**입니다.

따라서 향후 국가가 더 높은 시대에 진입해도 기존 `고대 주택`이 자동으로 `중세 주택`으로 이름만 바뀌지는 않습니다. 실제 개축·재건축·신축이 있어야 다른 세대의 건물이 됩니다.

#### 주거 3단계

- 🏠 **고대 주택** — 소규모 가옥군 · 4주거단위 · 수용 4
- 🏘️ **고대 연립주거** — 밀집 가옥군 · 8주거단위 · 수용 8
- 🏢 **고대 집합주거** — 대형 주거군 · 16주거단위 · 수용 16

기존 발전구조인

`house → row_house → collective_house`

는 그대로 유지합니다.

다만 Building 하나를 현실의 단독주택 한 채라기보다 **하나의 주거 개발 단위 / 가옥군**으로 해석합니다.

추가 표시명 예시:

- 고대 회관
- 고대 창고
- 고대 교역소
- 고대 시장
- 고대 상단 회관
- 고대 대시장
- 고대 학당
- 고대 항구
- 고대 채석장 / 고대 전문 채석장
- 고대 석재 가공장
- 고대 도로
- 고대 방책
- 고대 경작지

### 2. 국내 이주 churn 완화

V0.28 장기 데이터에서는 동일 Person이 여러 차례 이주하거나 `A → B → A` 형태로 되돌아가는 현상이 반복적으로 관찰됐습니다.

Patch 1에서는 국내 이주에 다음 안정장치를 추가했습니다.

- 실제 360일 달력을 기준으로 한 더 긴 이주 관성
- 이동거리 자체에 대한 마찰 비용
- 최근 떠난 정착지로 되돌아갈 때 추가 패널티
- 약 3년 이내 역이주에 강한 억제
- 일반 국가는 도시집약형보다 더 높은 이동 이득을 요구
- 주거 부족·극심한 지역 식량위기에서는 긴 쿨다운을 무시할 수 있는 긴급이주 유지
- 이주 직후 resident index/cache를 즉시 무효화해 거주지 판정 불일치를 방지

Person 개체와 `homeTileId`를 실제로 이동시키는 기존 철학은 그대로 유지합니다.

### 3. 생활권 과병합 수정

기존 V0.28 생활권은 연결요소 방식이었습니다.

예를 들어

`A ↔ B`, `B ↔ C`, `C ↔ D`

가 연결되면 A와 D 사이에 직접 관계가 거의 없어도 하나의 거대한 생활권으로 합쳐질 수 있었습니다.

장기주행에서는 일부 국가의 최대 생활권이 국민의 90% 이상, 수십 개 Settlement를 포함하는 단계까지 커졌습니다.

Patch 1에서는 생활권을 **hub-anchored 방식**으로 바꿨습니다.

- 강한 중심지를 생활권 hub로 선택
- 각 Settlement는 hub와 직접적인 통근관계 또는 제한된 공간적 근접성이 있어야 편입
- 다른 Settlement를 징검다리로 이용한 무제한 연쇄병합을 금지
- 생활권은 계속 행정구역이 아닌 관찰용 기능권역

따라서 V0.30의 City / Administrative Area와는 여전히 별개입니다.

### 4. 후기 Person 성능 최적화

88년 전후 장기주행에서 가장 큰 체감 문제는 후기 시뮬레이션 속도 저하였습니다.

프로파일상 UI 렌더링보다 **Person 일상 행동과 직업 재평가** 쪽 비용이 훨씬 컸습니다.

추적 과정에서 기술을 전부 연구한 뒤에도 모든 Person의 Knowledge 획득마다 오래된 연구 호환 루틴이 정착지 전체를 반복 확인하는 경로가 남아 있음을 확인했습니다.

Patch 1에서는:

- 모든 기술 연구 완료 후에도 Knowledge 총량·출처별 Knowledge는 계속 누적
- 이미 의미가 없어진 연구 선택/호환 작업은 우회
- 내부 Settlement 전체를 Person마다 반복 순회하는 후기 dead path 제거

를 적용했습니다.

Person 개체 자체를 집계값으로 바꾸거나 일상 행동을 삭제하지 않습니다.

### 5. 내부 물류 로그 압축

후기 devlog에서 `INTERNAL_LOGISTICS`가 상세 이벤트의 대부분을 차지해 수십 MB까지 커졌습니다.

Patch 1부터 같은 짧은 시간창 안에서 발생한 동일 경로의 물류 이벤트는:

- 국가
- 자원
- 출발 Settlement
- 도착 Settlement
- 운송 사유

별로 묶어 기록합니다. 또한 상세 `INTERNAL_LOGISTICS` 경로 로그는 최근 **5년**만 유지하고, 장기 추세는 yearly summary·snapshot·누적 물류 통계로 보존합니다.

집계 로그에는 다음 정보가 남습니다.

- 총 이동량
- 실제 moveCount
- 출발/도착 타일
- 사유
- 집계 기간

실제 자원 이동 횟수와 물량 자체는 기존 `logisticsStats` 및 V0.28 누적 통계에서 계속 계산됩니다. 즉 **시뮬레이션 물류를 줄이는 것이 아니라 로그 표현만 압축**합니다.

`V28_FOOD_ACCESS_BLOCKED` 같은 진단 이벤트는 그대로 유지합니다.

### 6. Settlement 상세 화면 정보 일치

기존 카드 요약에는 도시화 관련 핵심값이 잘 보였지만 상세 화면을 열면 오히려 일부 핵심 정보가 사라졌습니다.

Patch 1에서는 상세 화면 상단에 compact KPI를 추가했습니다.

- 촌락/마을/소도시/도시 등급
- 도시성
- 주민 / 실제 주거수용력
- 주거 점유율
- 평균 행복
- 평균 건물 condition
- 현지 근무자
- 통근 유입 / 유출
- 식량 비축일
- 평균 Hunger
- 분기 유지관리 필요량(목재 / 석재 / 노동일)

따라서 상세 화면은 카드 요약의 정보를 잃지 않고 더 깊은 정보를 이어서 볼 수 있습니다. 유지관리 값은 요약 카드에 표시되는 값과 동일한 문자열을 그대로 가져와 표시하므로 서로 다른 계산값이 보이지 않습니다.

### 7. 지도 도로 R 표시 스케일링

기존 지도에서는 `R1 / R2 / R3` 도로 레벨 표시에 최소 픽셀 크기가 고정되어 있어, 지도를 축소해도 라벨이 충분히 작아지지 않는 문제가 있었습니다.

Patch 1에서는:

- 라벨 배경 너비·높이
- 글자 크기
- 타일 내부 위치

를 현재 지도 `cell` 크기에 비례하도록 변경했습니다.

지도를 매우 축소해 타일이 충분히 작아지면 R 라벨 자체를 숨겨, 작은 지도에서 라벨이 지형·국경을 가리는 문제도 줄였습니다. 도로 선 자체와 실제 도로 레벨 효과는 변경하지 않았습니다.

### 8. 게임 내 패치노트와 버전 배지

상단의 `Village Observer · V0.28 P1` 표시를 실제 클릭 가능한 **버전 배지**로 변경했습니다.

배지를 누르면 게임을 벗어나지 않고 패치노트 모달을 열 수 있습니다.

구조는 정적 `PATCH_NOTES` 데이터이며 세이브 데이터와 분리됩니다.

- 최신 패치: 기본 펼침
- 이전 버전: 접힌 상태로 누적
- 현재 포함: `V0.28 P1`, `V0.28`
- 새 버전이 생기면 최신순으로 위에 추가 가능
- 모달은 기존 UI처럼 스크롤 가능
- ESC, 배경 클릭, 닫기 버튼 지원
- 모바일에서는 하단 시트에 가까운 배치와 더 큰 터치 영역 사용

패치노트 내용은 README를 대체하지 않습니다. README의 상세 내용을 바탕으로 핵심 변경만 압축한 요약입니다.

### 9. 건물 표시명 UI 통일 보강

건물의 실제 내부 ID는 그대로 유지하면서 사용자에게 보이는 이름은 `NS.BUILDINGS`의 현재 표시명을 기준으로 사용합니다.

따라서 정착지 카드·상세·백과·건설 진행·개축 진행·완료 연대기 등에서 가능한 한 같은 건물명이 사용됩니다.

레거시 `storehouse` 내부 ID도 사용자에게는 `고대 창고`로 표시해 `warehouse`와 시대명 체계를 맞췄습니다. 내부 ID를 합치거나 세이브 구조를 변경한 것은 아닙니다.

## V0.28 본체에서 유지되는 핵심 시스템

Patch 1에서도 아래 V0.28 설계는 그대로입니다.

- Person 기반 실제 국내 이주
- `homeTileId` / `workTileId` 분리
- 실제 통근
- Settlement별 emergent Urbanity
- 촌락 / 마을 / 소도시 / 도시 관찰 등급
- 주거압력에 따른 실제 신축·개축·토지개발

- 물리적 donor stock을 사용하는 도시 식량 접근 수송
- Settlement 집중도 / Gini / entropy / 통근 / 주거압박 / 식량스트레스 telemetry
- 실제 Person·Settlement·Building 보존

## 다음 단계
