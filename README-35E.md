# Village Observer V0.35E — Housing Demand Hotpath (2026-10-21)

## 개요

기준선: **V0.35D**, 기존 V0.35A~35D 계측 및 물류 최적화 유지. 지난 35D 실제 446일 진단에서 `demandDevelopment` 25회가 10,077.7ms를 사용했고, 그중 `settlementPressure` 3,003회는 약 30.9ms뿐이었습니다. 실제 병목의 정확한 하위 비용은 측정되지 않았으므로, V0.35E는 위험한 건설 재시도 생략 대신 **결과를 사용하지 않는 계산 제거 + 세부 경로 계측**에 집중합니다.

## 변경 사항

1. **V0.17 주택 후보 탐색**: 국가 영토별 `tileResidents()`를 호출해 `pop` 속성을 계산했지만 이후 이 값을 전혀 사용하지 않았습니다. 생성하지 않게 변경했습니다. 주거 압력 `settlementPressure()`, 타일별 평가, 순서, 건설 시도는 그대로 유지합니다.
2. **V0.32D3 생활권/행정권 순위**: `orderedHousingScopeD3()`가 같은 타일 간 거리를 순위 산정과 정렬용으로 중복 조회하던 경로를 **1회 조회**로 통합했습니다. 거리 공식, 선택 순서, tie-break, 행정 판단은 불변입니다.
3. **35E 주거·건설 정밀 진단**: 35D의 21개 분기 계층 진단과 함께 다음 8개 경로를 선택형으로 측정합니다: `demandDevelopment`, `buildHouseTop`, `buildHouseV17`, `housingRowsD3`, `tryHousingResolveD3`, `orderedHousingScopeD3`, `adminRegionKeyD3`, `tileBusyD3`. 호출 횟수, 반환값 진리값, 경과시간(포괄/측정 하위 제외), P95, 최대시간을 기록합니다. `houseEffects`에 **실패 후 텔레메트리 수 증가, 주거 상태 변경, 공사 건수 변경** 횟수도 기록합니다. 단, 이는 전체 상태의 완전한 부수효과 감사가 아니므로 실패 생략의 근거로 사용하지 않습니다.
4. **최초 화면 버전 표시 수정**: `NS.RELEASE_VERSION`, document title, `#versionBadge`를 35E 부트스트랩 종료 시 동기화하고 `UI.renderHeader()`에서도 유지합니다. 35D에서 발견된 35B 초기 배지 잔존 현상을 이번 정식 릴리스에 반영했습니다. Hosted의 캐시 매개변수도 35E로 갱신됩니다.
5. **포맷 및 배포**: 저장파일 버전 `V0.35E` (35D 및 이전 저장파일 로드 지원). `index.html`은 GitHub Pages Hosted 진입점, `index-standalone.html`/`dist/standalone/index.html`은 자체 포함 실행파일입니다. GitHub Desktop에서 프로젝트 폴더를 열고 루트 index 및 `dist/hosted/assets/`를 배포하세요.

## 하지 않은 변경

- `buildHouse()`의 실패 호출 생략, AI 행동 순서 변경, 주거 해결 우선순위 변경, 주택 비용·수용량·주거 예비자원 정책 변경 **없음**.
- 하루/분기 전역 캐시 **없음**. 보호 레거시 `src/legacy/*`의 원본 **169개 블록 불변**. 빌드 시에만 `tools/35e-transform.mjs`가 변환합니다.
- 35D 진단의 원인인 10.08초 전체에 대한 해결을 선언하지 않습니다. 이번 버전의 최적화는 해당 경로의 **일부 계산만 제거**하며, 세부 비용 비중은 90년대 실제 세계에서 다시 계측해야 합니다.

## 사용자 검증

1. V0.35E 최초 화면 상단 표시 확인.
2. 기존 **90년 세계 세이브** 로드.
3. 세계 → 고급 도구 → **35E · 주거·건설 분기 상세 계측** 시작.
4. 약 **180~360일** 자연주행 (실행 부담이 크면 분기 3~5개 정도). 다른 35A~35D 계측은 함께 켜지 않습니다.
5. 계측 종료 → `vilob-v035E-housing-<연도>y.json` 저장 후 전달.
6. 최종 성능 비교는 동일 세이브를 사용하고 **계측 OFF**로 35D/35E A/B 실행. `npm run bench:35e -- --save "<save.json>" --days 30 --warmup 3 --runs 3 --output ab.json`을 사용하면 Node VM 간 기본 비교가 가능합니다. 이 도구의 결과는 브라우저 10배속 SIM/BATCH 또는 Wall과 동일하지 않습니다.
