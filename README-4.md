# Village Observer V0.27

Village Observer는 실제 주민(Person)의 생활과 선택이 **Settlement → Nation → World** 변화로 이어지는 browser-based bottom-up 사회 시뮬레이션입니다.

V0.27은 V0.26 장기 테스트에서 확인된 두 문제를 집중적으로 처리합니다.

1. 약 900명 이후 `villageDaily`가 급격히 무거워져 ×10에서 체감 렉이 생기는 문제
2. 국가 전체 식량은 충분한데 일부 정착지에서 Hunger 100 집단 아사가 다시 발생하는 지역 분배 문제

도시화·철 경제 같은 새 콘텐츠보다 **수천 명 규모를 버틸 기반**을 우선 정비한 버전입니다.

---

## 1. Person 일상 처리 2차 최적화

V0.26 profiler에서 후반 SIM 시간의 80% 이상이 `villageDaily`에 집중되는 것이 확인됐습니다.

V0.27은 Person 개체를 삭제하거나 인구를 숫자로 추상화하지 않고, 같은 Person 시스템의 반복 계산을 줄입니다.

### 직업·근무지 재평가 스케줄링

기존에는 성인 Person이 매 작업일마다 직업과 근무지를 다시 평가하면서 국가 영토와 경로를 반복 탐색했습니다.

V0.27에서는 기존의 “하루 8% 확률로 직업 재고려”라는 의미를 유지하기 위해 **기하분포 기반 다음 재평가 시점**을 Person별로 예약합니다.

- 평소 작업일: 기존 직업/근무지 유지
- 예약된 재평가일: 기존 AI 점수로 직업·근무지를 다시 계산
- 근무지가 사라졌거나 타국 소유가 되는 등 상태가 무효해지면 즉시 재평가
- Person, 직업, 실제 근무지(`workTileId`)는 그대로 유지

즉 결과를 숫자로 대체한 것이 아니라 **필요할 때만 동일한 의사결정 계산을 수행**합니다.

---

## 2. 공유 일일 상태 캐시

Person마다 반복 계산되던 국가/정착지 공통값을 작업일 단위로 공유합니다.

주요 대상:

- 생존 Person ID 인덱스
- 정착지별 주민 목록
- 정착지 유효 주거 수용력
- 건물 Condition 기반 수용력
- 국가 치안 상태
- 국가 식량 스트레스 상태
- 가족 Person 조회

특히 행복 계산에서 부모를 찾기 위해 Person마다 국가 전체 주민 배열을 다시 검색하던 경로를 제거했습니다.

개인의 Hunger, Energy, Health, Happiness와 관계 데이터는 여전히 각 Person에 직접 존재하며 실제로 갱신됩니다.

---

## 3. 생산 기록 최적화

V0.26까지는 자연자원을 한 번 채취할 때마다 최근 150일 생산 기록 배열 전체를 다시 정리하는 경로가 존재했습니다.

V0.27에서는:

- 같은 날의 생산은 기존 일일 row에 O(1)로 누적
- 새로운 생산일이 시작될 때만 오래된 row 정리
- 최근 150일 생산 통계 의미는 유지

하도록 변경했습니다.

---

## 4. 내부 경로 캐시 2단계

V0.26의 장기 경로 캐시는 실제 경로 재계산은 많이 줄였지만, 캐시를 확인할 때마다 국가 전체 도로/항구 토폴로지 서명을 다시 계산하는 비용이 남아 있었습니다.

V0.27은:

- 국가 토폴로지 서명을 하루 한 번만 계산
- 동일 토폴로지에서 정착지 쌍의 경로비를 front-cache에 보존
- 영토/도로/항구/관련 기술 구성이 바뀌면 새 서명으로 캐시 교체

합니다.

---

## 5. ×10 Time-Sliced Simulation

V0.26에서는 ×10을 선택하면 10일을 한 번에 동기 계산했습니다. 총 계산량이 300~800ms가 되면 SIM 처리량 자체는 남아 있어도 브라우저 메인 스레드가 긴 시간 막혀 지도 드래그·클릭·탭 전환이 끊겨 보였습니다.

V0.27에서는 최근 SIM 비용과 인구에 따라 batch를 자동으로 쪼갭니다.

- 가벼운 세계: 최대 5일 단위
- 중간 부하: 2~3일 단위
- 약 900명 이상 또는 SIM 300ms 이상: **1일 단위**

각 chunk 사이에 브라우저가 입력과 화면 처리를 수행할 기회를 얻습니다.

HUD에는 기존 성능값과 함께 `SLICE`가 표시됩니다.

예:

`×10 · SIM 320ms/batch · 32ms/day · UI 4ms · SLICE 1d · HOT villageDaily ...`

SIM 값은 실제 계산시간의 합계이며, chunk 사이의 양보 시간은 별도 `perfWallMs27`로 기록합니다.

## 7. 지역 식량 분배 안정화

V0.26 장기 테스트에서는 국가 전체에 60~90일치 식량이 남아 있어도 특정 정착지에서 Hunger 100 집단 아사가 발생했습니다.

V0.27은 국가 공용 식량을 순간이동시키지 않습니다. 기존처럼 **실제 소유 정착지의 stock에서 다른 정착지 stock으로 내부 경로 용량만큼 이동**합니다.

### 선제 수송

주민 4명 이상 정착지는 대략 18일 미만의 지역 식량 또는 높은 Hunger가 감지되면 선제 수송 후보가 됩니다.

작은 개척지는 기존의 물류 긴장을 유지하기 위해 더 낮은 기준을 사용합니다.

### 긴급 수송

다음 상태에서는 긴급 모드가 됩니다.

- 지역 식량 약 8일 미만
- 심각한 Hunger 주민 존재
- 정착지 평균 Hunger가 매우 높음

이 경우 평시보다 높은 임시 수송용량을 사용할 수 있지만:

- 실제 donor 정착지가 존재해야 함
- donor도 최소 비축량을 남겨야 함
- 실제 내부 경로가 연결되어야 함

이라는 조건을 유지합니다.

따라서 국가 전체가 실제로 식량 부족이면 아사는 여전히 발생할 수 있습니다.

V0.27 추가 관측값:

- `preemptiveFoodMoves27`
- `criticalFoodMoves27`
- `foodReliefMoved27`
- `criticalFoodMoved27`

## 8. 주민 인덱스 추가 최적화

V0.26의 `tileResidents()`는 캐시된 주민 목록을 찾은 뒤에도 호환성을 위해 매번 배열 복사본을 만들었습니다.

V0.27에서는 내부 시스템이 캐시 배열을 읽기 전용으로 사용하도록 하여 이 복사를 제거합니다.

출생·사망·이주 시의 V0.26 자동 무효화 시스템은 그대로 유지합니다.

## 9. 지도 UI 수정

### 중립 타일 클릭

아무 국가에도 속하지 않은 타일을 선택하면:

- 타일 선택은 유지
- 기존 국가 선택은 해제
- 기존 Person 선택도 해제

됩니다.

### 국가 경계

국가색을 가리지 않으면서 큰 국가끼리 맞닿았을 때 더 잘 구분되도록 변경했습니다.

- **국가 ↔ 국가 경계:** 더 굵고 불투명한 검정선
- 국가 ↔ 중립/해안 경계: 그보다 얇은 어두운 선
- 선택 국가: 검정 국경 위에 얇은 해당 국가색 강조선
- 기존 국가색/지형 표현 유지

## 10. 개발 테스트 결과

환경과 세계 상태에 따라 결과는 달라질 수 있습니다.

동일한 약 1,560명·260여 점유타일 합성 상태의 ×10 계산 비교에서:

- V0.26: batch 중앙값 약 **1,057ms**
- V0.27: batch 중앙값 약 **360ms대**

로 감소했습니다.

V0.27은 여기에 1일 단위 time slicing까지 적용하므로, 총 batch가 300ms를 넘더라도 V0.26처럼 한 번에 300ms 이상 UI를 막지 않도록 설계했습니다.

15년 및 25년 헤드리스 회귀 테스트에서:

- 6개 국가 생존
- 저장 → 재로드 → 추가 진행 정상
- Person 타일 인덱스와 원본 주민 상태 일치
- 최근 생산 기록 150일 제한 정상
- 음수 stock/NaN Person 상태 미발견
- V0.27 CSV/Devlog 필드 생성 정상

을 확인했습니다.
