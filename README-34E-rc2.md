# Village Observer V0.34E-rc2 — E-02 이벤트 기록 경량화 및 로컬 A/B 검증

**날짜:** 2026-10-13  
**기준:** V0.34D3B3B → V0.34E-rc1 → V0.34E-rc2  
**상태:** 내부 실험판. 정식 V0.34E 성능 회복 완료가 아님.

## 이번에 실제 바뀐 것

1. **반복 이벤트 보존 필터 제거:** `src/legacy/016.js`의 오랜 수동 메모가 첫 원소로 남는 경우, 모든 새 이벤트마다 `entries.filter()` 전체 배열 순회가 반복될 수 있었습니다. 배포 빌드에서 해당 이벤트 보존 구간을 `ordinalDay` 최소 30 단위로 묶어 필요시에만 정리합니다. `yearlyEventCounts`, 이벤트 ID 증가, 수동 메모 보존, 전쟁/AI 이벤트 처리 래퍼, 로그가 게임 판단에 쓰이는 경로는 유지합니다. 이벤트 보존 기간 경계 부근의 정리 시점은 최대 30 ordinalDay 늦어질 수 있습니다.
2. **계측 관측자 부하 축소:** E-01 선택형 30일 계측에서 `stock.read`와 `food.reserveRead`의 수십만 개별 호출 타이머를 기본 목록에서 제외합니다. 해당 함수의 게임 실행 및 재고 처리는 바꾸지 않았습니다. 일반 플레이에서는 원래와 같이 계측 OFF입니다.
3. **브라우저 로컬 대용량 세이브 A/B 비교:** `tools/benchmark-local.html`을 추가했습니다. 사용자의 PC에서 **원본 61년차 세이브 JSON**, **B3B 단독 실행 HTML**, **E-rc2 단독 실행 HTML**을 파일 선택하고, 두 엔진을 순차·교차 실행해 순수 SIM 실행시간·RNG 호출·핵심 상태 지문을 비교합니다. 서버 업로드·인터넷 연결은 필요 없습니다. 135MB 세이브는 RAM 부담이 있으므로 무거운 탭을 닫아 주세요. 이 비교 도구는 Wall/Render를 측정하지 않으며 주요 상태의 해시만 대조합니다.
4. **Node 동일 월드 도구 개선:** `tools/benchmark-save.cjs`의 candidate 버전 표시를 업데이트하고 합성 후기세계용 `--synthetic-year`, `--synthetic-extra-people` 옵션을 추가했습니다. 실제 61년차 재현은 반드시 `--save` 사용.
5. **변경 회귀:** 180일 후기 합성세계의 RNG·주민·자원·전투 관련 주요 상태, Snapshot 횟수, 수동/시나리오 Snapshot, 저장 불러오기, 기존 48열 Food Flow를 검증합니다.

## 적용하지 않은 실험과 이유

**전체 자동 Snapshot 빈도를 낮추는 시도는 철회했습니다.** 구버전의 Snapshot 확장 래퍼 일부는 순수 관측이 아니라 실제 월드의 상태를 갱신합니다. 61년 설정 합성 세계에서 이를 건너뛰면 주민·자원·RNG가 달라졌습니다. rc2 최종 빌드는 **B3B와 동일한 자동 Snapshot 빈도**로 복구했습니다. 해당 래퍼의 상태 갱신/관측 분리는 후속 E 작업에서 합니다.

## 검증 성능 수치 (B3B와 rc2, 동일 시험 세계)

| 시험 | B3B | E-rc2 | 결과 |
|---|---:|---:|---|
| 오래된 수동 이벤트 1개 + 최근 1만 건, 이벤트 350건 추가 | 109.13ms | 38.39ms | **해당 기록 경로 64.82% 단축** |
| 61년 설정 합성 세계, 561명, 30일, 2회 교차 비교 중앙값 | 119.531ms/일 | 112.946ms/일 | **전체 SIM 5.51% 단축** |

**주의:** 실물 61년차 세계 556명·106 Settlement·전쟁 9건과 합성 61년·561명 세계는 다릅니다. 실물 세계에서 같은 개선율을 보장할 수 없고, 반복 수가 적어 측정 흔들림도 있습니다. 기존 사용자 보고 약 87ms/일과도 측정 실행환경(Node vs Chromium)이 다릅니다.

## 직접 수행할 실험 — 135MB 세이브를 전송하지 않아도 됨

1. `tools/benchmark-local.html`을 Chrome/Edge에서 엽니다.
2. 로컬 원본 61년차 세이브 JSON을 선택합니다.
3. B3B에서 다운로드한 **독립 실행형** `index.html`과 RC2의 `index.html`을 차례로 선택합니다 (두 파일을 서로 다른 폴더에 두면 편리).
4. **60일 × 2회** 교차 반복으로 시작합니다. PC 메모리가 충분하면 120일 × 3회도 가능합니다.
5. 측정이 끝나면 `semanticAndRngMatch`가 `true`인지 확인하고 `vilob-E02-61y-local-ab.json`만 대화에 올려 주세요. 이 파일은 작은 성능 요약이며 원본 세이브를 포함하지 않습니다.

세이브가 외부로 업로드되지 않도록 HTML은 서버 호출 코드를 포함하지 않습니다. 다만 실행에 필요한 두 HTML 파일의 코드는 사용자의 PC에서 그대로 실행하므로 **프로젝트의 신뢰할 수 있는 빌드만 선택**하세요.

## 유지된 사항과 미해결

- 원본 B3B의 실제 생산/소비/AI/전쟁/건설 밸런스 수식, 물리 재고, Save import, Snapshot V2 1683열, Food Flow 48열 유지.
- 기존 레거시 정적 기준 해시 유지(빌드 시 정해진 E02 전용 변환만 적용). 원본 완전 보존은 앞으로의 E 필수조건은 아닙니다.
- **미해결:** 61년차 실제 세이브의 동일 PC 속도 개선율, 복합 Snapshot 상태 갱신 분리, Food Flow 전쟁·점령 경로 잔차, 전체 장시간 npm test 종료 여부.
