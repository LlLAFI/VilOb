# Village Observer V0.32D2

**릴리스명:** 행정 제도화·효율 · Formation 이동 관측 · 정보 UI 마감  
**버전:** 0.32D2  
**기준 버전:** V0.32D1  
**세이브 키:** `village-observer-v0-32d2`

V0.32D2는 D 계열의 마감 패치다. D1 장기주행에서 확인된 행정권 코드 churn, 행정 중심지 이동 뒤 행정청 중복 건설, Formation 이동의 낮은 관측성, 철산업/군사시설 백과 노동량 누락, 좌상단 패치노트가 V0.32C까지만 보이던 초기 DOM 고정 문제를 정리한다.

이번 버전에서도 **전투·사상자·포로·점령·요새화는 추가하지 않는다.** D2의 목적은 기존 행정·군사 이동 시스템이 장기 자연주행에서 역사성과 관측성을 갖도록 완성하는 것이다.

## 1. 행정권 V1.2: 임시 → 정식 → 제도화

### 1.1 임시 행정권

새로운 비수도 행정 중심지 후보가 나타나도 즉시 B/C/D 같은 영구 코드를 발급하지 않는다.

- 최초 등장 후 약 **1년(360 calendar days)** 동안 `·` 임시 행정권으로 관찰한다.
- 임시 중심지가 인근 타일로 소폭 이동하면 같은 임시 후보의 연속성으로 본다.
- 1년을 채우지 못하고 사라진 후보는 알파벳을 소비하지 않는다.

이 변경은 D1에서 C/E/G처럼 연간 Snapshot에도 남지 못할 정도로 짧은 행정 중심지가 영구 코드를 소비하던 현상을 완화한다.

기존 세이브에서 이미 발급된 `A/H/I` 같은 코드는 재번호화하지 않는다. 과거에 생겼다가 사라진 행정권의 흔적은 세계의 행정사로 보존한다.

### 1.2 정식 행정권

임시 행정권이 1년 이상 유지되면 국가별 발급 순서에 따라 B/C/D… 코드를 받는다.

- 한 번 발급된 코드는 재사용하지 않는다.
- 수도권 A는 항상 유지한다.
- 행정청이 없는 정식 행정권은 여전히 비교적 유동적이다.
- 기존 D1 세이브의 정식 코드는 D2에서 그대로 승계한다.

### 1.3 행정청과 제도화

비수도 정식 행정권이 **6년 이상 안정**되고 기존 행정청 건설 조건을 만족하면 고대 행정청을 건설한다.

고대 행정청 기본 사양:

- 목재 34
- 석재 22
- 골드 0
- 건축공간 1.8
- 총 노동량 900 adult-day

행정청이 완공된 권역은 `제도화된 행정권`이 된다.

제도화 이후에는 단기적인 인구·도시성·행정점수 변동으로 쉽게 폐지되지 않는다. 기존 중심이 국가 영토 안에 유지되는 한, 기본 행정 중심지 계산에서 잠시 제외되어도 권역 자체는 유지될 수 있다.

### 1.4 행정 중심 이전의 강한 관성

제도화된 행정권의 중심은 새로운 후보가 잠깐 더 높은 점수를 얻었다고 즉시 이동하지 않는다.

- 새 후보가 기존 중심보다 충분히 높은 행정점수를 확보해야 한다.
- 그 우위가 약 **4년(1,440 calendar days)** 지속되어야 정상적인 중심 이전을 허용한다.
- 기존 중심 타일 자체를 상실한 경우에는 즉시 새 중심으로 이전할 수 있다.

따라서 장기간 제도화된 H권역 등이 계절별 계산 변화만으로 H → 새 코드 → H 식으로 흔들리는 현상을 억제한다.

### 1.5 행정청은 타일이 아니라 행정권에 귀속

D1에서는 행정청 존재 여부를 현재 중심 타일만 보고 판단했기 때문에, H권역의 중심이 `52 → 73 → 72`처럼 이동하면 기존 타일 52에 행정청이 있어도 새 중심마다 행정청을 다시 지을 수 있었다.

D2에서는 행정청의 귀속 단위를 `regionCode`로 변경한다.

예:

- H 행정권 현재 중심: tile 72
- H 행정청: tile 52

이 상태도 정상이다. 행정 중심은 사회·경제 변화에 따라 이동할 수 있지만 기존 행정청은 H권역의 지역 행정기관으로 계속 인정된다.

같은 행정권에 운영 가능한 행정청이 이미 있으면 중심 이동 후 추가 행정청을 착공하지 않는다.

## 2. 행정 효율

행정권은 생산량·저장량·인구·자원을 직접 증가시키지 않는다. D2의 행정 효과는 **기존 자원과 노동을 운용할 때 발생하는 마찰을 줄이는 방식**이다.

### 2.1 행정 효율 지표

제도화된 행정권에는 0~100의 행정 효율을 계산한다.

행정 효율은 다음이 커질수록 떨어진다.

- 권역 인구
- 권역 Settlement 수
- 행정 중심까지의 평균 경로비용

따라서 국가가 커져 하나의 행정청이 너무 넓은 지역을 담당하면 효율이 자연스럽게 하락한다. 이것은 장기적으로 새로운 행정권 분할이 필요한 신호가 된다.

수도권 A는 중앙 행정 기반이 이미 존재하는 것으로 간주하여 제도화 상태로 취급한다.

### 2.2 내부 물류 효율

같은 제도화 행정권 안에서 이동하는 내부 물류는 행정 효율에 비례해 거리 마찰을 완화한다.

- 최대 약 **10%**의 유효 경로비용 완화
- 물류 capacity는 감소한 마찰만큼 완만하게 증가
- 실제 Food/Wood/Stone 등 재고 자체는 생성하지 않음
- 기존 출발 Settlement에서 실제 자원을 차감해 목적지로 이동하는 보존 규칙 유지

즉 행정청이 있다고 식량이나 목재가 생기는 것이 아니라, 같은 양의 자원을 지역 안에서 더 효율적으로 조직하고 전달한다.

### 2.3 원격 유지보수 효율

같은 제도화 행정권 안에서 발생하는 원격 유지보수 임무는 행정 효율에 비례해 왕복 이동 손실을 줄인다.

- 최대 약 **12%** 이동일 감소
- 실제 유지보수 작업자의 수와 노동일은 그대로 필요
- 건물 Condition 회복량을 직접 생성하지 않음

D2 telemetry에는 누적 물류 경로비 절감량과 유지보수 이동일 절감량을 별도로 기록한다.

## 3. Formation 이동 관측 개선

D1에서 Formation의 실제 이동은 정상적으로 발화했지만, 지도에는 현재 위치만 표시되어 분기 단위 로그를 보면 먼 거리를 순간이동한 것처럼 보일 수 있었다.

D2는 이동 규칙을 바꾸지 않고 관측을 강화한다.

### 3.1 실제 이동 규칙 유지

- 약 **15 calendar days마다 인접 자국 타일 1칸** 이동
- 개별 병사 pathfinding이 아니라 Formation 단위 경로 계산
- 실제 병력은 Field Cohort에 속한 Person ID
- 전투는 비활성

### 3.2 군사 지도 표시

군사 레이어에서 다음을 표시한다.

- `■N`: 고정 Garrison
- `▲N`: 현재 Formation 위치
- 점선: 현재 위치에서 목표까지의 예정 경로
- 흐린 실선: 최근 지나온 최대 3타일
- `◎`: 현재 목표 타일

지도 범례에도 `15일/칸` 규칙을 표시한다.

### 3.3 군사 상세

Formation 카드와 선택 타일 상세에 다음 정보를 추가한다.

- 현재 임무/목표 이유
- 목표까지 남은 타일 수
- 다음 이동까지 예상 남은 날짜
- 예정 경로 타일
- 누적 이동 칸 수

D1의 이동 속도 자체는 우선 유지한다. D2 장기주행에서 경로가 보이는 상태에서도 너무 빠르다고 느껴질 경우 후속 버전에서 20~30일/칸 조정을 검토한다.

## 4. 백과: 철산업·군사시설 명칭과 노동량

시대 접두어 규칙에 맞춰 다음 표시명을 사용한다.

- 철광산 → **고대 철광산**
- 제련소 → **고대 제련소**
- 대장간 → **고대 대장간**
- 고대 병영
- 고대 훈련장
- 고대 무기고

기존에는 이 6개 시설이 `TOTAL_LABOR25` 기준표에 빠져 있어 실제 공사에서는 fallback 600 adult-day를 사용하면서도 백과에는 노동량이 표시되지 않았다.

D2에서는 다음 6종의 기본 노동량을 **명시적으로 600 adult-day**로 등록한다.

- 고대 철광산: 600
- 고대 제련소: 600
- 고대 대장간: 600
- 고대 병영: 600
- 고대 훈련장: 600
- 고대 무기고: 600

`PUBLIC_WORKS` 등 기존 기술 효과가 있으면 실제 프로젝트 노동량은 이 기준보다 감소할 수 있다. D2는 이번 패치에서 시설별 노동량 밸런스 자체를 새로 차등화하지 않는다.

## 5. 인게임 패치노트 구조 수정

V0.28에서 생성된 패치노트 DOM은 처음 한 번 만들어진 뒤 `dataset.ready` 상태로 고정되었다. 게임 UI 인스턴스가 C 계열 스크립트 이전에 생성되면서, 이후 D/D1 패치노트 데이터가 `NS.PATCH_NOTES`에 추가되어도 좌상단 버튼의 실제 화면은 V0.32C까지만 남을 수 있었다.

D2에서는 좌상단 버전 버튼을 열 때마다 **현재 `NS.PATCH_NOTES` 배열을 기준으로 패치노트 HTML을 다시 생성**한다.

따라서 D2 이후 후속 버전도 패치노트 데이터만 정상 등록하면 같은 버튼에 최신 항목이 반영된다.

D2 패치노트는 다음 구조로 작성한다.

- 행정권 제도화
- 행정 효율
- Formation 관측
- 백과·명칭
- 패치노트·관측

## 7. 세이브 호환성

D2 저장 버전은 `0.32D2`이다.

불러오기 fallback 순서는 D1 → D → C2 이하 순서다. 기존 D1의 `v32dAdmin.labels`, `activeSince`, `lastSeen`과 행정청 건물을 읽어 D2 `regionMeta`를 구성한다.

기존에 이미 발급된 행정권 코드는 재번호화하지 않는다. 예를 들어 D1 세이브에서 A/H/I가 남아 있었다면 D2에서도 A/H/I를 유지한다.

## 8. 범위 제한

D2에서는 다음을 추가하지 않는다.

- 전쟁 선포
- 전투 판정
- 전사/부상/포로
- 점령/영토 변경
- 임시/영구 요새화
- 후기 식량 시스템 대규모 리밸런싱
- 기술트리 추가
- 철산업 생산량 재밸런싱

이 항목들은 D 계열이 안정된 뒤 V0.32E 이후 범위다.

- 기존 행정청이 있으면 `tryAdminOffice` 추가 착공 **0건**

### 제도화 중심 이전

H권역 시나리오에서:

- 기존 H 중심: tile 3

- H 행정청은 tile 3에 그대로 귀속
- H 코드 유지

- 기존 유효 경로비 1.0
- D2 적용 후 0.9
