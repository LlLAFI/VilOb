# Village Observer V0.32D

**버전:** V0.32D  
**리비전:** `formation-map-stats-admin-terrain-log-compression`  
**기준 버전:** V0.32C2  
**세이브 버전:** `0.32D`  
**localStorage 키:** `village-observer-v0-32d`

## 1. 버전 목적

V0.32D는 V0.32 군사사회 단계에서 처음으로 **실제 현역 병력을 지도 위에 지속적으로 존재하는 Formation으로 관측**할 수 있게 하는 버전이다. 동시에 V0.32C2의 123년 장기주행에서 드러난 관측·UI·로그 문제를 정리한다.

이번 버전의 핵심 범위는 다음과 같다.

- 실제 Person 기반 `Formation` V1 및 군사 지도 레이어
- 통계 탭 그룹형 선택 UI와 한국어 표기 정리
- 행정권 A/B/C 영속 코드와 고대 행정청
- 국가 중심 / 균형 / 지형 중심 지도 표현
- 목재·석재·철광석 초기 가격 정상화
- 장기 Devlog 고빈도 이벤트 압축 2차
- 식량 접근 차단·긴급 수송·아사 누적 관측 강화

**전투, 사상자, 포로, 점령, 영토 변경은 V0.32D에 포함하지 않는다.** V0.32E/F에서 다룰 예정이다.

## 2. Formation V1

### 2.1 기본 원칙

V0.32D의 Formation은 가상의 병력 숫자가 아니다.

- 현역 군인은 계속 실제 `Person`이다.
- 기존 `MilitaryCohort.memberIds`가 실제 Person ID를 보유한다.
- `Formation`은 하나 이상의 Cohort를 참조하는 지도상 이동 단위다.
- Formation 자체가 새로운 사람을 만들지 않는다.
- Formation의 병력 수는 참조 Cohort에 포함된 **생존 + 현역 상태 Person 수**로 계산한다.

따라서 Formation 생성·이동만으로 세계 인구가 증가하거나 감소하지 않는다.

### 2.2 Garrison과 Formation

- **Garrison:** 부대의 고정 주둔 거점/본거지 역할
- **Formation:** 실제로 지도 위를 이동하는 야전부대 역할

Formation이 본거지를 떠나면 연결된 Garrison은 `DEPLOYED` 상태로 표시될 수 있다. 현재는 전투가 없으므로 Garrison과 Formation 사이의 전투력 분할은 하지 않는다.

### 2.3 Formation 상태

현재 상태값은 다음과 같다.

- `GARRISONED`: 본거지 주둔
- `MOVING`: 목표 타일로 이동 중
- `DEFENDING`: 목표 전략 타일에 도착해 방어 중
- `HOLD`: 목표 경로를 확보하지 못해 대기
- `INACTIVE`: 참조하는 실제 현역 Person이 없음

### 2.4 이동

- Formation은 정확한 `tileId`를 가진다.
- 이동은 **Formation 단위**로 계산한다. 개별 병사가 각각 pathfinding하지 않는다.
- 기본 이동 주기는 약 15 calendar days다.
- 한 번의 이동에서 인접한 자국 영토 타일 한 칸을 이동한다.
- 도로가 있는 타일은 경로 비용이 낮다.
- 타국 영토와 통과 불가능 지형은 현재 경로에서 제외한다.

이 설계는 실제 Person 구조를 유지하면서도 병력 이동을 집단 단위로 처리해 성능 부담을 제한하기 위한 것이다.

### 2.5 AI 전략 목표

Formation의 전략 목표는 약 90 calendar days 단위로 재평가한다. 주요 평가 요소는 다음과 같다.

- 외국과 접하는 국경 타일
- 외교 관계에서 계산되는 국경 위험
- 국가의 군사적 경계 수준
- 행정 중심지
- 수도
- 철광산·제련소·대장간 등 철산업 시설
- 철광 매장지
- 병영·훈련장·무기고
- 도로
- 해당 타일 인구
- 현재 Formation 위치와의 거리
- 군사 교리

교리에 따라 `FORWARD`, `CAUTIOUS`, `RESOURCE_GUARD`, `URBAN_GUARD`, `ECONOMY_FIRST`, `BALANCED`가 서로 다른 전략 타일을 선호한다.

Survival Mode에 들어간 국가는 Formation 목표를 본거지 방향으로 되돌린다.

### 2.6 군사 지도 레이어

지도 레이어에 **군사**가 추가된다.

- 한 Formation: `▲병력수`
- 한 타일에 복수 Formation: `⚔총병력수`

마커의 병력 수는 실제 현역 Person 수다.

타일 상세에서는 다음을 확인할 수 있다.

- 국가
- Formation 이름
- 실제 Person 병력 수
- 현재 상태
- 훈련
- 장비율
- 사기
- 보급
- 목표 타일

국가의 군사 화면에도 Formation 목록과 현재 위치/목표 위치/이동 횟수가 추가된다.

## 3. 통계 탭 개편

V0.32D에서는 비슷한 지표를 그룹형 드롭다운으로 통합했다.

### 3.1 생활 상태

기존의 별도 지표였던 다음 항목을 **생활 상태**로 통합한다.

- 평균 건강
- 평균 허기
- 평균 행복

### 3.2 지식

기존 `누적 Knowledge`를 **지식** 그룹으로 변경한다.

세계 범위:

- 누적 지식
- 국가별 평균 지식
- 1인당 지식

국가 범위:

- 누적 지식
- 1인당 지식

`1인당 지식 = 누적 지식 / 인구`로 계산한다.

### 3.3 골드

기존 `Gold`와 `국가 금고 Gold`는 사실상 같은 국고 값을 중복 표시하고 있었으므로 그룹형 지표로 정리했다.

세계/국가 범위의 **골드** 그룹:

- 전체/국내 통화량
- 국가 금고 골드
- 정착지 시장 골드
- 개인 보유 골드

정착지 범위:

- 정착지 시장 골드
- 1인당 시장 골드

전체 통화량과 국가 금고는 서로 다른 값이므로 별도로 유지한다.

`전체 통화량 = 국가 금고 + 정착지 시장 + 개인 지갑` 구조를 관측한다.

기존 `관측 Gold 순증가 / 순감소` 그래프는 통계 UI에서 제거했다. 다만 Gold 보존 오류 탐지를 위한 내부 audit telemetry는 그대로 유지한다.

### 3.4 한국어 표기

통계 탭에서 사용자에게 노출되는 핵심 지표는 한국어 중심으로 정리했다.

- Hunger → 허기
- Knowledge → 지식
- Settlement → 정착지
- Person → 개인/인구 맥락에 맞는 한국어
- Gold → **골드**

내부 필드명과 개발 telemetry의 영문 키는 호환성을 위해 유지할 수 있다.

### 3.5 통계 렌더 안정화

- 드롭다운 option DOM은 선택지가 실제로 달라질 때만 재생성한다.
- 현재 열린 select의 DOM을 틱마다 교체하지 않는다.
- 통계 canvas는 실제 픽셀 크기가 달라질 때만 재설정한다.
- `전체 통화량`처럼 V0.32C1a에서 깜빡임이 관찰됐던 사용자 지정 골드 지표도 동일한 단일 렌더 경로를 사용한다.

### 3.6 정착지 건강/행복 과거 기록

정착지 단위 평균 건강·평균 행복의 연간 필드는 V0.32D부터 저장된다. 이전 버전의 과거 데이터에 존재하지 않는 값을 임의로 역산하지 않는다.

## 5. 행정권 V1.1

### 5.1 A/B/C 영속 코드

기존에는 여러 행정 중심지가 존재해도 지도상 식별이 명확하지 않았다.

V0.32D에서는 국가 내부 행정권에 다음과 같은 코드를 부여한다.

- 수도 행정권: `A`
- 이후 생기는 행정권: `B`, `C`, `D`, `E` ...

코드는 단순한 화면 순번이 아니라 해당 행정 중심지 타일에 저장되는 영속 식별자다. 행정 점수 재계산 때마다 B가 C로 바뀌는 식의 불필요한 흔들림을 피한다.

행정 중심지에서 일시적으로 탈락했다가 다시 중심지가 된 경우에는 기존 코드를 재사용한다. 단, 안정기간은 다시 계산한다.

### 5.2 행정 중심지 안정기간

각 행정 중심지가 현재 지위를 연속으로 유지한 기간을 기록한다.

- 수도 A는 기본 행정 핵심으로 유지한다.
- 비수도 행정 중심지는 중심지에서 탈락하면 연속 유지기간이 초기화된다.
- V0.32C2 이하 세이브에서 마이그레이션할 때 과거 중심지 이력을 임의로 만들어내지 않는다. 마이그레이션 시점부터 안정기간을 관측한다.

### 5.3 고대 행정청

비수도 행정 중심지가 **연속 6년** 동안 행정 중심지 지위를 유지하면 `고대 행정청` 건설 대상이 된다.

조건:

- 행정제도 기술 보유
- 해당 Settlement가 현재 비수도 행정 중심지
- 연속 6년 이상 유지
- Survival Mode가 아님
- 식량 비축 30일 이상
- 건축공간 확보
- 같은 타일에 행정청 또는 진행 중 행정청 공사가 없음

건설비:

- 목재 34
- 석재 22
- 골드 0
- 총 노동량 900 adult-day

행정청은 일반 개발보다 높은 전략 우선순위로 분기 시작 전에 착공을 시도한다. 다른 공사가 막고 있던 슬롯이 해제되는 경우에도 다시 시도한다. 생존 위기보다 우선하지는 않는다.

현재 V0.32D에서는 행정청 자체의 세금·보급·군사 보너스는 최소화했다. 이후 행정·군사·광역물류 시스템의 실제 허브로 확장할 수 있도록 물리적 건물만 먼저 도입한다.

## 6. 지도 표현 방식

지도 툴바에 영토 표현 선택기가 추가된다.

### 국가 중심

- 국가 영토색 약 40%
- 국가 구분을 가장 쉽게 확인

### 균형

- 기존 수준인 약 30%
- 지형과 국가색을 동시에 확인

### 지형 중심

- 국가 영토색 약 9% 수준
- 평야·숲·암지·산악 등 지형색을 우선 확인
- 국가 간 검은 국경선은 계속 유지

행정권·군사 등 분석 레이어는 선택한 지도 표현 위에 계속 표시할 수 있다.

## 7. Devlog 압축 2차

123년 장기주행에서 Devlog가 50MB를 넘었고, 고빈도 이벤트가 대부분의 용량을 차지했다.

V0.32D는 **최근 5년은 상세 로그를 유지하고, 그보다 오래된 일부 고빈도 이벤트를 연간 요약 이벤트로 변환**한다.

압축 대상:

- `INTERNAL_LOGISTICS`
- `V28_FOOD_ACCESS_BLOCKED`
- `EMERGENCY_FOOD_CONVOY`
- `TREASURY_RESERVE_BLOCK`
- `MILITARY_SLOT_RESERVED32C1`
- `MILITARY_SLOT_RESERVED32C2`

과거 상세 이벤트는 `LOG_SUMMARY32D`로 집계한다. 집계에는 가능한 범위에서 다음을 남긴다.

- 원래 이벤트 종류
- 국가
- 자원/원인/건물 종류
- 이벤트 횟수
- 총 이동량
- 최대 평균 Hunger 관측값
- severe Hunger 관측 합계
- 관련 타일 수
- Gold 차단 총액

최근 5년 상세 이벤트는 원형 그대로 유지하므로 최근 위기의 원인 추적이 가능하다.

Formation 이동 로그도 매 타일마다 무제한 신규 이벤트를 만드는 대신 **Formation + 분기 단위로 묶어서 갱신**한다.

## 8. 식량 접근성 관측 강화

V0.32C2의 110년 이후 장기주행에서는 세계 총 식량뿐 아니라 Settlement별 식량 접근 실패가 구조적 문제로 드러났다.

V0.32D에서는 식량 물류 밸런스 자체를 크게 변경하지 않는다. 대신 다음 누적 telemetry를 추가한다.

- `foodAccessBlocked32D`
- `emergencyConvoys32D`
- `starvationDeaths32D`

세계와 국가 snapshot에서 장기 변화를 비교할 수 있다.

이 문제는 Formation 도입과 동시에 물류 규칙까지 크게 바꾸면 원인 분리가 어려우므로, 광역 식량망 자체의 재설계는 후속 버전으로 미룬다.

## 9. 저장·호환성

### 저장

- 세이브 버전: `0.32D`
- localStorage: `village-observer-v0-32d`

Formation과 행정권 상태가 저장된다.

Formation 저장 항목 예:

- Formation ID
- Nation ID
- Cohort ID 목록
- 현재 `tileId`
- 본거지 `homeTileId`
- 목표 `targetTileId`
- 상태
- 이동 횟수
- 최근 이동/계획 시점

행정 저장 항목 예:

- 타일별 A/B/C 코드
- 중심지 연속 유지 시작일
- 다음 행정권 코드 순번
- 행정청 착공 통계

### 이전 버전 호환

V0.32C2 및 이전 V0.32/0.31 계열 localStorage를 fallback으로 읽는다.

V0.32C2 → V0.32D 마이그레이션 시:

- 인구를 그대로 유지한다.
- 기존 실제 MilitaryCohort를 사용해 Formation을 생성한다.
- 합성 병력을 만들지 않는다.
- 행정권 코드는 현재 행정 구조를 기준으로 처음 부여한다.
- 6년 행정 안정기간은 마이그레이션 시점부터 새로 측정한다.
- 오래 진행된 세이브의 현재 시장가격은 초기 가격으로 강제 초기화하지 않는다.

## 11. V0.32D에서 관찰할 항목

다음 실제 장기주행에서는 특히 아래를 확인한다.

2. Formation이 국경/철산업/행정 중심지로 자연스럽게 이동하는지

6. 첫 고대 행정청 착공/완공 연도
7. 지형 중심 모드에서 영토와 지형을 동시에 읽기 편한지
8. 통계 탭 드롭다운과 전체 통화량 그래프 깜빡임이 사라졌는지
9. 100~130년 Devlog 크기가 C2 대비 얼마나 감소했는지
10. `foodAccessBlocked32D`, `emergencyConvoys32D`, `starvationDeaths32D`의 후기 추세
11. 2,000~3,000 Person 구간 SIM 성능
