# Village Observer V0.32C2

## 버전 개요

**V0.32C2 「군사 공동재정 통일 · 성능 최적화 2차 · 통계 안정화」**는 V0.32C1a의 약 99년 장기주행에서 확인된 세 가지 핵심 문제를 보정한다.

1. 군사시설 계획 단계에서는 Settlement 시장 Gold를 포함해 건설 가능으로 판정하지만 실제 `payBuild()`에서는 구형 Treasury-only 준비금 검사에 다시 막히던 문제
2. 인구 1,000명 이상에서 `Person.act`의 직업 검토 전처리가 전체 주민·영토를 불필요하게 반복 순회하던 후기 성능 문제
3. `세계 → 전체 통화량 → 전체 기간` 등 V0.30 Gold 계열 통계가 실제 canvas를 한 틱에 두 번 그려 깜빡이던 문제

추가로 V0.32C1 계열에서 지나치게 많이 쌓이던 군사 전략 슬롯 차단 로그를 분기 집계형으로 정리한다.

---

## 1. 군사시설 공동재정 결제 경로 통일

### 기존 문제

V0.32C1a의 병영·훈련장·무기고 후보 판정은 V0.31H의 전략 공동재정 `funding()`을 사용한다. 이 계산은 국가 안의 Settlement 시장 잉여 Gold와 국가 Treasury 준비금 초과분을 함께 본다.

하지만 실제 건설 결제는 더 오래된 V0.30B2 준비금 검사까지 다시 통과해야 했다. 이때 군사시설에 대한 시장 지원이 `marketSupport = 0`으로 재평가되면서 다음과 같은 모순이 발생했다.

- 계획기: 자금 충분
- 전략 슬롯: 군사시설용으로 예약
- 실제 결제: `TREASURY_RESERVE_BLOCK`
- 결과: 특히 무기고가 수십 년간 후보 상태로만 남을 수 있음

### C2 수정

병영·훈련장·무기고는 사전 판정과 실제 결제에서 같은 전략 공동재정 규칙을 사용한다.

- V0.31H `funding()`으로 실제 건설 가능 Gold를 먼저 검증한다.
- 각 Settlement 시장의 유동성 reserve를 초과하는 Gold만 사용한다.
- 국가 Treasury는 전략 준비금 초과분만 사용한다.
- 필요한 경우 같은 국가의 다른 Settlement 시장 잉여 Gold를 실제로 이전한다.
- Gold는 새로 생성되지 않는다.
- 위 전략 검증을 통과한 군사시설에 한해서만 구형 Treasury-only 중복 검사를 우회한다.
- 실제 공사가 재료 부족 등으로 실패하면 이전했던 시장 Gold를 원위치로 되돌린다.

### 표적 검증

인구 40명, Treasury 5G, 해당 Settlement 시장 100G 조건에서 무기고 10G 건설을 강제했다.

- Treasury: **5G → 5G**
- 시장 Gold: **100G → 90G**
- 무기고 공사: **실제 착공 성공**
- `TREASURY_RESERVE_BLOCK(armory)`: **0건**
- `MILITARY_MARKET_POOL32C2`: 정상 기록

완성된 무기고 + 대장간 + 실제 철공 1명을 둔 생산 테스트에서는 군사장비 **1.65세트**가 생성되었고 다음 자원이 실제로 감소했다.

- 철: **-1.188**
- 목재: **-0.297**
- 도구: **-0.07425**

따라서 기존 C의 `철 + 목재 + 도구 → 군사장비` 보존형 생산 경로가 실제 무기고 활성화 뒤 정상 작동한다.

## 2. Person 성능 최적화 2차

### 병목 원인

V0.29의 `chooseJob()`은 실제 직업 재검토 시점을 45~210일 정도 뒤로 예약해 두고도, 함수에 들어올 때마다 먼저 `ensureNation29()`를 호출했다.

`ensureNation29()`는 모든 주민과 모든 영토 타일의 V0.29 상태를 확인한다. 따라서 이미 직업이 안정되어 있고 다음 재검토 시점도 멀리 남은 Person까지 매 작업 사이클마다 국가 전체 주민 목록을 반복 스캔하게 된다.

인구가 커질수록 이 반복 비용이 `Person.act`의 주요 후기 병목으로 커졌다.

### C2 빠른 경로

C2는 **직업 자체의 선택 규칙을 변경하지 않는다.** 다음 조건을 모두 만족하는 안정적인 시민만 구형 `chooseJob()` 진입을 건너뛴다.

- 성인
- 개척민이 아님
- 현재 직업이 정상적인 직업군에 속함
- 무직이 아님
- 거주지가 여전히 자국 영토임
- 예약된 다음 직업 검토 시점이 아직 오지 않음
- 노동구조 강제 갱신 플래그가 없음
- 시설 직업인 경우 기존 실제 슬롯·근무 건물·근무 타일이 모두 유효함

다음 경우에는 **항상 기존 `chooseJob()`을 그대로 호출**한다.

- 정기 직업 재검토 시점 도달
- 무직
- 노동구조 변경
- 거주지 이상
- 직업 값 이상
- 농부·광부·상인·학자·철공의 시설 슬롯이 없어졌거나 불일치

15세 미만 아동은 기존과 동일하게 `아이`, 근무지=거주지 상태만 유지하고 국가 전체 노동 인덱스 검사를 생략한다.

### 중요한 비변경 영역

이번 최적화에서는 `metabolism()`을 다시 구현하지 않는다. 따라서 다음 기존 경로는 그대로 유지된다.

- Hunger / Energy / Health / Happiness
- 질병과 사망
- 주거 압박
- 축제 행복도
- 식량 소비량
- Knowledge 계산
- 생산과 채굴
- 건설·유지보수 전업
- 현역 군복무
- 철광산·제련소·대장간 특수 행동
- Hunger 100의 12 calendar day 유예

### 행동 동등성 테스트

같은 V0.32C1a 저장 상태를 C1a와 C2에 각각 불러오고 `Math.random()`을 동일한 값으로 고정해 한 작업 사이클을 비교했다.

일반 성인 목수와 아동 모두 다음 값이 정확히 일치했다.

- Hunger
- Energy
- Health
- Happiness / Happiness Target
- 식량 및 생산 자원 변화
- Knowledge 증가량
- 직업
- 행동 문구

### 마이크로벤치마크

아래 수치는 **전체 SIM 시간이 아니라, 안정적인 시민의 `chooseJob()` 호출 경로만 비교한 값**이다. 각 조건은 워밍업 뒤 3회 평균이다.

| 안정 시민 수 | V0.32C1a | V0.32C2 |
|---:|---:|---:|
| 600명 | 약 35.03ms | 약 0.53ms |
| 1,600명 | 약 256.43ms | 약 0.90ms |

실제 자연주행에서는 물류·건설·유지보수·경제·사회·특수 직업 계산도 함께 작동하므로 전체 SIM 개선폭은 이 표보다 작다. 후기 1,000~2,000 Person 구간은 실제 사용자 장기주행 데이터로 다시 확인한다.

## 3. Gold 통계 차트 깜빡임 보정

### 원인

V0.30 Gold 계열 사용자 정의 지표는 기존 통계 UI를 재사용하기 위해 임시로 `population`을 그린 뒤 같은 실제 canvas 위에 Gold 지표를 다시 그리는 구조였다.

따라서 `평균 건강` 같은 기본 지표는 실제 canvas를 틱당 1회 그리지만 `전체 통화량` 등은 같은 틱에서 2회 그릴 수 있었다. 여기에 canvas `width/height` 재설정이 겹치면 화면 깜빡임으로 보일 수 있다.

### C2 수정

세계/국가/Settlement의 V0.30 Gold 계열 사용자 정의 지표는:

1. 기존 통계 wrapper와 selector 갱신을 **분리된 임시 canvas**에서 수행하고
2. 실제 `statsCanvas`에는 최종 그래프만 **틱당 1회** 그린다.
3. 실제 픽셀 크기가 변하지 않았으면 canvas의 `width/height`를 다시 할당하지 않는다.

V0.32C1a의 드롭다운 option DOM 보호도 그대로 유지한다.

표적 테스트에서 `세계 → 전체 통화량 → 전체 기간`을 두 번 연속 렌더했을 때 실제 `statsCanvas.getContext()` 호출은 총 2회, 즉 **렌더당 1회**였다. 기본 지표도 같은 조건에서 렌더당 1회였다.

## 4. 군사 전략 슬롯 로그 집계

V0.32C1a에서는 동일한 군사시설 슬롯 하나 때문에 주택·도로·창고·채석시설 등이 차단될 때 각각 별도 `MILITARY_SLOT_RESERVED32C1` 이벤트가 생성될 수 있었다.

C2는 같은 **국가 + 목표 군사시설 + 분기**의 차단을 `MILITARY_SLOT_RESERVED32C2` 한 건으로 집계한다.

집계 payload에는 다음을 유지한다.

- `blockedTypes`: 차단된 건물 종류
- `reasons`: 차단 사유
- `blockedAttempts`: 총 차단 시도 횟수
- 공사 수 / 공사 한도
- 군사시설 가용 funding / 필요 Gold

표적 테스트에서 C1 형식 12회 기록 요청은 C2 이벤트 **1건**, `blockedAttempts = 12`로 보존되었다.

## 8. 다음 장기주행에서 볼 항목

V0.32C2에서는 약 90~105년까지 다음을 우선 확인한다.

1. 무기고가 실제 자연 착공하는가
2. `MILITARY_EQUIPMENT_PRODUCED32C`가 자연 발생하는가
3. 장비 생산 시 철·목재·도구가 실제 감소하는가
4. Cohort `equipment %`가 0을 벗어나는가
5. 1,000~2,000명 구간의 `SIM / villageDaily / personActEst`가 C1a보다 얼마나 낮아지는가
6. `세계 → 전체 통화량 → 전체 기간` 깜빡임이 실제 UI에서도 사라졌는가
7. `MILITARY_SLOT_RESERVED32C2` 로그가 이전처럼 폭증하지 않는가

이 검증이 통과하면 V0.32D의 지도 위 Formation 위치·군사 레이어·부대 이동으로 진행한다.
