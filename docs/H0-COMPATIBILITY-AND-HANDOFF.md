# H0 호환성 경계와 H1 인계

## 세이브 호환성

- 보장 검사: H0 자체 직렬화/역직렬화, G5 저장 JSON, G4A1 형식 변환(G5 회귀).
- G5 코드의 자동 복원 키 G4A/G4/G3B는 유지되었지만 각 버전의 실제 장기 사용자 세이브로 직접 검증하지는 않았다.
- V0.33 이하 저장파일 지원 의무는 제거. 하지만 `World.from` 구형 래퍼를 물리적으로 덜어내면 G4/G5의 의존 사슬도 잘릴 가능성이 있어 H0에서는 유지했다.

## 삭제 분류와 위치

| 소스 | H0 처리 | 다음 |
|---|---|---|
| legacy/163.js 고정 C1G 성공 배너 | 정확한 코드 한 줄만 빌드 변환에서 제거 | H3 경고 체계 정식 통합 |
| g3aRuntimeIntegrity 성공 문구 | G5 검사 유지, 화면 성공상태만 숨김 | H3 개발자 패널에서 검사 상세 |
| legacy/040.js lifezone 지도 레이어 | 보존 | H1 레이어 UI 제거 |
| legacy/091.js engagements33C 통계 패널 | 보존 | H3 전쟁 기록 통합 후 제거 |
| 기존 World.from 체인 | 보존 | H1~H3 종료 뒤 실제 0.34 의존 테스트로 분리 검토 |
| F0/F1 UI | 보존 | H3 세계 탭 이동, 계산/샘플링 불변 |

## 변경 지점

- C1H SHA 소스 직접 편집 금지, H0 변환과 bootstrap을 이용.
- 새 UI 컴포넌트는 `NS.V034H0.ui`의 선택적 헬퍼 사용 가능. renderHeader의 H0 마지막 래퍼는 남겨두어야 정상/오류 상태가 유지됨.
- 새 버전 개발 시 마지막 bootstrap과 `RELEASE_VERSION`, `World.serialize`, `World.from`, Telemetry 버전 체인을 한꺼번에 갱신할 것.
