# Village Observer V0.34G1B — Settlement-first UI

**기준:** V0.34G1A (2026-10-16) · **패치 범위:** 한국어 UI와 표시 정보 구조만 변경, 시뮬레이션·물류·AI·RNG 무변경.

## 합의한 화면 설계

- **국가 → 정착지:** 기본 선택. `Settlement` 1개당 **상세 카드 1개**를 카드 그리드(PC 2열, 모바일 1열)로 표시. 선택/펼치지 않아도 정착지 인구와 공동 주거·식량·목재·석재·철광·철·도구·시설 종류 및 수·평균 건강/행복/Hunger·주민 직업이 보인다. 구성 타일은 필요할 때만 펼친다.
- **국가 → 타일:** 1타일당 작은 한 줄 목록. 좌표·지형·거주자·실제 시설 개수·소속 정착지를 표시. 타일 항목을 누르면 실제 **물리 재고**와 시설을 보여주고 지도에서 더 자세히 볼 수 있다.
- **지도 → 타일 클릭 하단 상세:** 기존 코드와 UI를 그대로 보존.
- UI 용어는 `Tile = 타일`, `Settlement = 정착지`. `마을/도시`는 정착지의 도시화·발전 상태에 대한 설명에서 사용한다.

## 공동 재고/주거 표시

- `NS.V034D2.context(v,w)`의 정착지 엔티티 및 구성 타일, `Village.stockAt(coreId, resource)`의 공동 식량/물자 총량, `Village.settlementCaps(coreId)`의 전체 저장 용량을 각각 읽는다.
- 개별 타일 상세는 `NS.V034D3.stockRaw(w,id,k)`와 `NS.V034D3.physicalCap(v,id,k)`를 사용해 **한 타일에 실제 놓인 수량/용량**만 표시한다. 공동 재고를 타일 수만큼 반복 집계하지 않는다.
- 인구·평균 Health/Happiness/Hunger·직업은 현재 소속된 실제 주민의 `homeTileId`를 정착지 구성 타일에 매핑해 한 번씩 집계한다.
- 도시화 수치: 기존 V28 타일별 관측 캐시에 값이 있을 때에만 거주 인구 가중 평균을 **UI 관측값**으로 표기하고, 캐시가 없다면 `미집계`. 새로운 도시화 게임 규칙을 만들지 않는다.
- 식량 비축은 F2 주민의 연령별 3일 배급 수요를 분모로 사용하는 `settlementReserveDays` 결과이며, 이전 구형 타일 UI의 `일` 오류를 반복하지 않고 **작업주기(3일)**로 표시한다. 화면 외 다른 구형 국가 경제 및 통계 지표 전체의 단위 개편은 이번 범위 밖이다.
- 건물 수와 시설 상태는 해당 정착지에 속한 타일에서만 집계한다.

## 관측 및 시뮬레이션 범위

- 기존 G1A의 `sampleDays`, 식량 수요 누락, 동일 정착지 배송 및 CSV/Devlog 감사 로직은 **전혀 수정하지 않는다.** `G1A 물류 감사 CSV` 버튼 역시 계속 사용한다.
- 30일과 90일 주행 G1A↔G1B 인구, 식량 비축, Health, Happiness, 물리 식량, 영토, RNG 호출 수 비교 일치.
- 180일 비교는 실행 시간 제한으로 **미완료**. 따라서 180일 PASS를 주장하지 않는다.
- 새로운 정착지 단위 외부 배송·같은 정착지 배송 제거는 **V0.34G2**, 원형 최대 반경 AND 도로 접근 비용 개편은 **V0.34G3**.

## 실행/빌드

- HTML 단독 실행: `index-standalone.html` 혹은 `dist/standalone/index.html`.
- GitHub Pages: 루트 `index.html`과 `dist/hosted/assets/` 디렉터리 함께 업로드.
- 빌드: `npm run build`.
- 정적/30일 검사: `npm test`.
- 브라우저 확인: `python tests/browser-g1b-smoke.py`.
- G1A 기준선 90일 비교: `G1_DAYS=90 node tests/test-g1b.cjs`.
- 이전 G1A 일반 세이브 직접 가져오기와 G1B 재저장 지원. G1B 신규 로컬 저장 키를 쓰며 이전 G1A 로컬 저장 키를 자동으로 찾는다.
