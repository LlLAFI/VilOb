# V0.34E-rc4h — Snapshot 결정론 핫픽스

- **기준**: RC4 → RC4h; 정식 V0.34E 배포가 아닌 내부 검증판.
- **동기**: 61년차 실물 세이브 B3B/RC3 대비 RC4의 종료 인구 556→558, RNG 127,530→127,686회(+156), 최종 상태 지문 불일치.
- **핵심 조치**: RC4에서 성능 목적으로 생략했던 `src/legacy/119.js`(F5 통화·가격)와 `src/legacy/122.js`(F5A 개척 재정)의 Snapshot `attach(w)` 호출을 **RC3와 바이트 단위로 동일하게 복구**. 이 경로에는 `_v29SettlementCache` 무효화와 여러 세대의 `attachWorld` 상태 보정이 포함된다. 개별 무효화만 임의로 추측해 복원하지 않고 호출 연쇄를 정확하게 되돌렸다.
- **보존**: RC2의 이벤트 기록 일괄 정리, RC3의 주거·개척 Snapshot 상태 갱신 분리, RC4의 3일 주기 선택형 프로파일러 및 로컬 A/B 브라우저 도구를 유지.
- **정확성 근거**: 182개 인라인 스크립트 가운데 마지막 버전·저장/계측/UI 스크립트만 RC3와 달라지고 **앞의 실행 스크립트 181개가 완전히 동일**함을 테스트로 확인. RC3 ↔ RC4h 150일 직접 비교 10개 체크포인트, 주거/개척 상태, RNG, 반복 수동 Snapshot이 일치. B3B와 60일 짧은 합성 세계 상태·RNG도 일치. 작은 세이브 Chromium 로컬 A/B 30일 ×1에서 상태·RNG·Snapshot 호출이 일치.
- **제한**: 사용자의 135MB짜리 실제 61년차 세이브를 실행하지 못했으므로, 실물 세이브에서의 완전한 결정론 복구 및 SIM 개선율은 아직 **사용자 로컬 재검증 대기**. 검사 지문은 포괄적이지 않음. RC4의 이전 10.75% 개선을 RC4h에 귀속하지 않는다. 이 핫픽스는 안전성을 위해 RC4 Snapshot 성능 단축 일부/전부를 포기한 것.
- **주의**: RC4 실행 중 **이미 저장한 새로운 세이브**에 반영된 인구/RNG 차이는 핫픽스가 거꾸로 되돌릴 수 없다. **RC4 업데이트 이전의 원본 B3B/RC3 61년차 세이브**를 테스트 시작점으로 사용하는 것을 권장. RC4 형식 저장파일의 수동 가져오기는 가능하지만 기존 RC4 게임 상태는 동일 결과의 증거로 사용할 수 없다.

## 소스 구성

`tools/e4-transform.mjs`는 두 Snapshot의 원래 `attach(w)` 호출을 검사하고 보존하는 **안전성 게이트**로 전환되었다. 보호되는 원본 169개 레거시 블록은 변경하지 않는다. `tools/build.mjs`는 Standalone/Hosted에 동일한 F5/F5A 복구 경로를 반영한다.

## 사용자 61년 세이브 시험

1. `benchmark-local.html`을 Chrome 또는 Edge에서 실행하고 사용자 PC의 **RC4 이전 원본** `61y.json`을 선택.
2. 비교 기준: **RC3** (`index-RC3-baseline.html`); 후보: **RC4h** (`index.html`).
3. **60일 × 2회 교차 비교** 실행. 결과에서 `semanticRngAndSnapshotMatch: true`, `population`, `rngCalls`, `finalFingerprint`, `snapshotCalls` 일치를 확인.
4. 비교 목적에 따라 B3B 기준으로도 시험 가능. **일치가 실패하면 해당 RC4h 릴리스를 즉시 회귀 실패로 취급**하고 결과 JSON을 공유.
5. 같은 물리 상태에서 다른 처리시간이 관측돼도 2회가 충분히 안정적이지 않다면 반복 횟수를 늘려 판단.
