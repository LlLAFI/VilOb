# Village Observer V0.34E-rc1 — E-01 성능 계측 기반

- 날짜: 2026-10-13
- 이전 기준선: **V0.34D3B3B**
- 배포 형태: **0.34E 내부 RC1**, 정식 V0.34E가 아님
- 범위: 프로파일러, 저장파일 A/B 비교 실행기, 중복/레거시 코드 정적 감사

## 이번 실험판의 실제 변경

1. `src/bootstrap/v034e.js` 추가. 게임 세계 화면의 성능 관측 아래에 `0.34E 실험실` 패널을 추가하고, 다음 **30일 동안만** 선택적으로 세계/주민/식량/정착지/AI/텔레메트리 실행시간을 수집합니다. 완료 또는 수동 중지 시 설치한 프로파일러 함수를 전부 복구합니다. 평소 OFF 상태에는 메서드별 호출 계측을 설치하지 않습니다.
2. `tools/benchmark-save.cjs` 신규. 원본 B3B와 E-rc1을 별개 Node VM에 로드해 **동일 저장파일·동일 난수 시드**로 하루 시뮬레이션을 반복 실행합니다. 전체 `World.advanceOneDay()` 시간의 반복 중앙값, RNG 호출 수, 주요 실제 상태의 SHA-256 지문 일치 여부를 출력합니다.
3. `tools/audit-surface.mjs` 신규. 과거 레거시와 부트스트랩의 함수 재할당 위치 및 관측 코드 분포를 정적으로 집계합니다. 실행시간을 의미하거나 삭제 허용 여부를 보장하지 않습니다.
4. `tests/test-e01.cjs` 신규. B3B↔E 동일 시드 15일 동작, 프로파일러 자동 종료 및 원본 함수 복구, 세이브 가져오기, 기존 Food Flow 48열을 검증합니다.
5. 기존 B3B 실제 시뮬레이션 로직 및 경제·전쟁·AI·소모 수식은 수정하지 않았습니다. 구버전 저장 스키마 및 기존 CSV 스키마는 이번 RC에서 유지합니다.

## 사용법 — 브라우저

`index.html` (단독 실행)을 열고, **세계 → 성능 관측 → 0.34E 실험실**의 `다음 30일 계측`을 누릅니다. 시뮬레이션을 진행하면 30일 후 자동 중지됩니다. `성능 JSON 내보내기`를 누르면 상세 항목별 호출 횟수와 exclusive/inclusive 시간이 저장됩니다. 30일이 끝나지 않았다면 `계측 중지`를 누릅니다. 계측 ON 수치는 측정 자체의 오버헤드가 있으므로 평상시 B3B의 SIM/Wall과 직접 비교하지 마세요.

## 사용법 — 원본 61년차 세이브 B3B vs E 비교

Node.js 18 이상에서 프로젝트 폴더를 연 뒤 실행합니다.

```bash
node tools/benchmark-save.cjs --save "C:/path/to/your-61y-save.json" --days 30 --runs 5 --output perf-61y.json
```

인자 없이 시험할 수도 있습니다. 다만 그 경우 **새 월드 성능시험**이며 61년차 비교가 아닙니다.

```bash
node tools/benchmark-save.cjs --days 15 --runs 3 --output perf-fresh.json
```

- `--profile` 은 E 후보에서 중첩함수의 exclusive 시간·호출 수를 출력하지만, 계측 자체가 오버헤드를 만들기 때문에 **성능 개선율 판정에는 쓰지 마세요**. 주로 병목 조사에 사용합니다.
- 반복 횟수 `--runs`마다 B3B/E의 실행 순서를 교대합니다.
- 고정된 VM 난수 발생기를 적용합니다. 이전 브라우저 자연주행의 RNG 연속성을 재현한다는 의미는 아닙니다. **같은 저장 상태에서 두 버전의 RNG 호출·주요 상태를 비교**합니다.
- `changePercent` 는 Node VM 안에서의 SIM 처리시간 변화이고 **브라우저 Wall/Render나 실제 PC 장기 체감속도가 아닙니다**.
- A/B 결과가 다르면 `semanticStateAndRngMatch=false`로 기록하고 종료코드 2를 반환합니다.
