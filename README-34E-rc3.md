# Village Observer V0.34E-rc3 — 개발 실험판

기준선: V0.34E-rc2 (이전 V0.34D3B3B 호환). 날짜: 2026-10-13.
**정식 V0.34E 출시가 아닌 중간 RC**이며, 실제 61년차 135MB 세이브는 개발 환경에 없으므로 성능 합격을 아직 확정하지 않았다.

## 변경사항

1. **Snapshot 관측과 상태 갱신의 단계 구분**: 원본 V0.32D3 `src/legacy/065.js`에서 Snapshot 확장 도중 호출하던 주거·개척 상태 갱신을 `advanceSnapshotStateD3()`로 분리했다. 실행 시점은 **기존 상위 Snapshot 생성 완료 직후 그대로** 유지한다. 관측 기록 생성과 주거·개척 상태 갱신의 책임을 명확히 하되, 상태 갱신을 완전히 독립된 World 스케줄러로 이전하거나 Snapshot 호출 주기를 줄이는 작업은 **이번 RC에서 하지 않았다**. 기존 데이터·RNG 동등성 우선.
2. **개척 진단 반복 탐색 경량화**: `regionalEligibilityD3()`에서 각 개척 출발 타일마다 재검사하던 주민 적격성·홈 타일 조회를 1회 사전 정리하고, 진행 중인 개척 프로젝트 출발점도 Set으로 조회한다. 최종 판정 순서, 주민 이동, 국고, 연구, 개척 규칙은 변경하지 않았다. 권위 있는 `tileResidents()`는 그대로 사용하여 주거·군사·민간 상태를 잘못 합치지 않는다.
3. **로컬 A/B 도구 E-03**: 2회/짝수 회차의 중앙값을 두 가운데 값의 평균으로 수정. Snapshot 배열 길이 변화 대신 **실제 함수 호출 수**, 측정된 Snapshot 시간, 사유별 횟수, 일자별 SIM 시간, 추가 상태 지문을 기록. 교차 실행·브라우저 파일 선택은 유지. 상태 지문은 여전히 *선택된 주요 의미 필드*에 한정하며 완전한 이진 일치 검사는 아니다.
4. **저장 호환**: RC1·RC2·B3B 저장파일 가져오기 허용. 로컬 저장키와 다운로드 파일명은 RC3로 갱신.
5. **검증 및 배포**: Hosted(GitHub Pages) 및 독립 실행판 생성, PC·모바일 Chromium 확인.

## 적용하지 않은 작업

- Snapshot 자동 생성 주기 감소: 이전 RC2 실험에서 게임 상태/난수가 달라져 이번에도 변경하지 않음.
- 모든 과거 Snapshot 래퍼/CSV 삭제: 통계 및 시뮬레이션 상태 의존성을 아직 확인해야 함.
- 경제·군사·AI·식량 밸런스 변경, 새로운 물류 정책: 없음.
- `World.advanceOneDay()` 전면 재작성: 프로파일과 회귀 필요하여 후속 RC로 이관.

## 실행

- `index-standalone.html` 또는 `dist/standalone/index.html`: 브라우저에서 직접 열기.
- `index.html` 및 `dist/hosted/` 경로: GitHub Pages 구조. GitHub 루트 배포 시 `dist/hosted/assets/` 폴더도 배포해야 함.
- `tools/benchmark-local.html`을 브라우저에서 열고 **원본 B3B 저장 JSON + B3B 독립 HTML + RC3 독립 HTML**을 선택. 권장 60일 × 2회. 내보낸 JSON만 전달.
- 저장 JSON은 사용자의 PC 브라우저에서 읽으며 앱의 외부 서버로 전송하지 않음. 대용량 세이브는 메모리 부담이 크므로 다른 탭 종료 권장.

## 알려진 한계

- 후기 자연주행 실측 성능 목표 20~30% 개선은 아직 검증되지 않음.
- RC3 합성 세계 벤치마크의 개선율은 반복 편차가 크므로 실물 PC A/B 시험으로 검증할 것.
- Snapshot의 데이터 변경은 별도 함수로 묶였지만 호출 시점은 여전히 Snapshot 경계와 결합되어 있음.
- `Food Flow` 잔차 178건(별도 전쟁 동시발생 관측) 원인 수정은 이번 작업 범위 밖.
